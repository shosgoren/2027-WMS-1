**protected: true** (beyan; onay değildir) — kök ve `packages/db` `package.json` `scripts` alanı.
**Amaç (tek cümle):** ADR-015'teki elle yazılmış SQL up/down çiftlerini migration rolüyle uygulayan/geri alan, uygulanmış dosyanın özet değişikliğini reddeden koşturucuyu ve `wms_app` rolünü denetleyen ilk migration'ı yazıp `pnpm test:int`'in her koşuda migration'larla başlamasını sağlamak.
**Okuma listesi (≤5):** `docs/adr/ADR-015.md`, `docs/INVARIANTS.md I-02, I-03`, `packages/db/src/client.ts` (tamamı, ~150 satır), `tests/integration/harness/global-setup.ts`, `infra/postgres/init/01-roles.sh`
**Dokunulacak dosyalar (≤10):** `packages/db/src/migrate.ts`, `packages/db/src/migrate-cli.ts`, `packages/db/src/migrate.test.ts`, `packages/db/migrations/0001_baseline.up.sql`, `packages/db/migrations/0001_baseline.down.sql`, `packages/db/package.json`, `package.json`, `tests/integration/harness/global-setup.ts`, `tests/integration/migrations.int.test.ts`

**Yapılacaklar:**
1. `migrate.ts`: `NNNN_<ad>.up.sql`/`.down.sql` çiftlerini okur (çiftsiz dosya, numara boşluğu/yinelenmesi → hata); `wms_meta.schema_migrations(version, name, checksum_sha256, applied_at, applied_by)` defteri; her migration tek transaction; koşu kilidi `pg_advisory_xact_lock` (doğrudan bağlantı). Uygulanmış sürümün dosya özeti farklı → `MIGRATION_CHECKSUM_MISMATCH`, hiçbir şey uygulanmaz.
2. Bağlantı yalnızca `DATABASE_URL_DIRECT`; `current_user` = `wms_app` ise ret (`MIGRATION_WRONG_ROLE`). URL/parola hiçbir çıktıda yok (G-09). `postgres.js` mevcut sürücü; yeni bağımlılık yok.
3. `migrate-cli.ts` + betikler: kök `db:migrate`, `db:rollback` (`-- --to NNNN`; yalnızca `WMS_ENV` ∈ `local|ci|staging`, aksi ret) → `@wms/db` paket betiklerine yönlenir. CLAUDE.md'de geçen `pnpm db:reset` bu kartta **yazılmaz** (kapsam dışı; bulgu olarak raporla).
4. `0001_baseline.up.sql`: `wms_app` rolü yoksa veya `rolsuper`/`rolbypassrls` true ise `RAISE EXCEPTION`; `REVOKE CREATE ON SCHEMA public FROM PUBLIC`; `GRANT USAGE ON SCHEMA public TO wms_app`; `wms_meta` şeması (sahibi migration rolü, `wms_app`'e yetki yok). `down`: yalnızca kendi eklediklerini geri alır (defter tablosu koşturucunundur).
5. `global-setup.ts`: compose ve neon hedeflerinde testlerden önce `migrate up` (migration rolü). Mevcut `rls-probe` fikstürü ve AC-05/AC-28 testleri değişmeden yeşil kalır.
6. `migrate.test.ts` (unit): dosya eşleştirme, numara kuralları, özet hesabı. `migrations.int.test.ts`: ileri → tümüyle geri → ileri hatasız; geri sonrası `public`'te uygulama tablosu yok; özet değiştirilmiş geçici kopyada ret; `DATABASE_URL` ile çalıştırmada ret.

**Kabul ölçütü:** `pnpm verify` OK; `pnpm test:int` → yeni testler + mevcut harness/AC-05/AC-28 PASS (özet satırı); `pnpm db:migrate` iki kez art arda → ikincisi "0 bekleyen"; `pnpm check:all` → protected yalnızca beyan edilen `scripts` değişikliğini gösterir.
**Kapsam dışı:** Uygulama tabloları (T-102+), Neon'da rol oluşturma (T-105), dağıtım adımı (T-106), `db:reset`.
**Gerekli inceleme:** security-reviewer zorunlu + bağımsız qa (T-104) — RLS/rol (I-03). Paket `int/faz1-sema` (bu kart paketin ilk kartı).
