# T-103: Tenant, üyelik, rol, davet, ayar tabloları (RLS) + `withMembership` / `withUser` / `withNewTenant` / `withSystemTenant`
**Faz:** 1 · **Ajan:** db-engineer · **Bağımlılık:** T-102 · **Dal:** `feat/T-103-tenancy` → `int/faz1-sema`
**Amaç (tek cümle):** ADR-016 §2–3, §5–6, §8'deki tenant/üyelik şemasını RLS şablonuyla kurmak ve üyeliği yazmayla aynı transaction'da (`FOR SHARE`) doğrulayan `withMembership` ailesini `packages/db`'ye eklemek.
**Okuma listesi (≤5):** `docs/adr/ADR-016.md`, `docs/adr/ADR-015.md §5`, `packages/db/src/with-tenant.ts` + `packages/db/src/client.ts` (`createTenantContext`, `TenantTx`), `docs/spec/15-engineering.md §DB sözleşmesi, §API sözleşmesi (hata kodları)`, `docs/INVARIANTS.md I-01, I-02`
**Dokunulacak dosyalar (≤10):** `packages/db/migrations/0003_tenancy.up.sql`, `packages/db/migrations/0003_tenancy.down.sql`, `packages/db/src/schema/tenancy.ts`, `packages/db/src/schema/index.ts`, `packages/db/src/with-membership.ts`, `packages/db/src/with-membership.test.ts`, `packages/db/src/index.ts`, `tests/integration/with-membership.int.test.ts`, `tests/integration/schema/drift.int.test.ts`, `tests/integration/migrations-nonsuper.int.test.ts`

**Yapılacaklar:**
1. Tablolar ADR-016 §2–3'teki sütunlarla: `tenants`, `tenant_memberships`, `membership_roles` (`role_key` CHECK: `TENANT_ADMIN|WAREHOUSE_MANAGER|PICKER|COUNTER|READ_ONLY`), `invitations` (yalnızca `token_hash`; `UNIQUE (token_hash)`; aktif davet için `(tenant_id, email_normalized)` kısmi benzersiz), `tenant_settings`. Tenant tablolarında `(tenant_id, id)` benzersiz + bileşik FK; `ON DELETE CASCADE` zinciri yok (15 §DB sözleşmesi).
2. RLS: ADR-015 §5 şablonu; `tenant_memberships` ek **SELECT** politikası `user_id = NULLIF(current_setting('app.current_user_id', true), '')::uuid`; `tenants` okuma: kendi tenant'ı veya `app.current_user_id`'nin ACTIVE üyeliği; yazma yalnızca `id = current_tenant`. `wms_app` GRANT'ları tablo başına en dar (`tenants`: DELETE yok).
3. `withMembership({ client, userId, tenantId, permission? }, fn)`: ADR-016 §5 akışı; `permission` denetimi için izin matrisi **parametre olarak** alınır (`(roles) => boolean` veya `allowedRoles`), matrisin kendisi T-113'te `packages/domain`'dedir (db iş kuralı bilmez). Ret kodları `FORBIDDEN`, `TENANT_SUSPENDED`, `TENANT_CLOSING` (15 §Hata kodları); geçersiz UUID → sorgusuz ret.
4. `withUser(client, userId, fn)` (yalnızca `app.current_user_id`), `withNewTenant(client, { tenantId, userId }, fn)` (yeni tenant + sahip üyeliği tek transaction'da, RLS atlanmadan), `withSystemTenant(client, tenantId, reason, fn)` (tenant ACTIVE değilse ret). Hepsi `set_config(..., true)` + aynı `tx` (I-02); `SET`/string birleştirme yok.
5. Son sahip kuralının DB tarafı: sahip üyelikleri `FOR UPDATE` ile kilitleyen yardımcı (`lockOwners(tx, tenantId)`); kural kararı T-117'de.
6. `with-membership.test.ts` (unit): girdi doğrulama. `with-membership.int.test.ts`: aktif üyelik → `fn` çalışır; REMOVED → FORBIDDEN; SUSPENDED → TENANT_SUSPENDED; başka tenant'ın slug/id'si → FORBIDDEN; **yarış:** A transaction'ı `withMembership` içinde beklerken B çıkarmayı commit etmeye çalışır → B bekler; tersi sırada A reddedilir. `drift.int.test.ts` yeni tablolarla genişler.
