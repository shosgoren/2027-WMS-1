# T-103: Tenant, üyelik, rol, davet, ayar tabloları (RLS) + `withMembership` / `withUser` / `withNewTenant` / `withSystemTenant`
**Faz:** 1 · **Ajan:** db-engineer · **Bağımlılık:** T-102 · **Dal:** `feat/T-103-tenancy` → `int/faz1-sema`
**Amaç (tek cümle):** ADR-016 §2–3, §5–6, §8'deki tenant/üyelik şemasını RLS şablonuyla kurmak ve üyeliği yazmayla aynı transaction'da (`FOR SHARE`) doğrulayan `withMembership` ailesini `packages/db`'ye eklemek.
**Okuma listesi (≤5):** `docs/adr/ADR-016.md`, `docs/adr/ADR-015.md §5`, `packages/db/src/with-tenant.ts` + `packages/db/src/client.ts` (`createTenantContext`, `TenantTx`), `docs/spec/15-engineering.md §DB sözleşmesi, §API sözleşmesi (hata kodları)`, `docs/INVARIANTS.md I-01, I-02`
**Dokunulacak dosyalar (≤10):** `packages/db/migrations/0003_tenancy.up.sql`, `packages/db/migrations/0003_tenancy.down.sql`, `packages/db/src/schema/tenancy.ts`, `packages/db/src/schema/index.ts`, `packages/db/src/with-membership.ts`, `packages/db/src/with-membership.test.ts`, `packages/db/src/index.ts`, `tests/integration/with-membership.int.test.ts`, `tests/integration/schema/drift.int.test.ts`

**Yapılacaklar:**
1. Tablolar ADR-016 §2–3'teki sütunlarla: `tenants`, `tenant_memberships`, `membership_roles` (`role_key` CHECK: `TENANT_ADMIN|WAREHOUSE_MANAGER|PICKER|COUNTER|READ_ONLY`), `invitations` (yalnızca `token_hash`; `UNIQUE (token_hash)`; aktif davet için `(tenant_id, email_normalized)` kısmi benzersiz), `tenant_settings`. Tenant tablolarında `(tenant_id, id)` benzersiz + bileşik FK; `ON DELETE CASCADE` zinciri yok (15 §DB sözleşmesi).
2. RLS: ADR-015 §5 şablonu; `tenant_memberships` ek **SELECT** politikası `user_id = NULLIF(current_setting('app.current_user_id', true), '')::uuid`; `tenants` okuma: kendi tenant'ı veya `app.current_user_id`'nin ACTIVE üyeliği; yazma yalnızca `id = current_tenant`. `wms_app` GRANT'ları tablo başına en dar (`tenants`: DELETE yok).
3. `withMembership({ client, userId, tenantId, permission? }, fn)`: ADR-016 §5 akışı; `permission` denetimi için izin matrisi **parametre olarak** alınır (`(roles) => boolean` veya `allowedRoles`), matrisin kendisi T-113'te `packages/domain`'dedir (db iş kuralı bilmez). Ret kodları `FORBIDDEN`, `TENANT_SUSPENDED`, `TENANT_CLOSING` (15 §Hata kodları); geçersiz UUID → sorgusuz ret.
4. `withUser(client, userId, fn)` (yalnızca `app.current_user_id`), `withNewTenant(client, { tenantId, userId }, fn)` (yeni tenant + sahip üyeliği tek transaction'da, RLS atlanmadan), `withSystemTenant(client, tenantId, reason, fn)` (tenant ACTIVE değilse ret). Hepsi `set_config(..., true)` + aynı `tx` (I-02); `SET`/string birleştirme yok.
5. Son sahip kuralının DB tarafı: sahip üyelikleri `FOR UPDATE` ile kilitleyen yardımcı (`lockOwners(tx, tenantId)`); kural kararı T-117'de.
6. `with-membership.test.ts` (unit): girdi doğrulama. `with-membership.int.test.ts`: aktif üyelik → `fn` çalışır; REMOVED → FORBIDDEN; SUSPENDED → TENANT_SUSPENDED; başka tenant'ın slug/id'si → FORBIDDEN; **yarış:** A transaction'ı `withMembership` içinde beklerken B çıkarmayı commit etmeye çalışır → B bekler; tersi sırada A reddedilir. `drift.int.test.ts` yeni tablolarla genişler.

**İnceleme eki (security-reviewer @ 83b5bea):**
- M4: `tenant_memberships.roles_version int NOT NULL DEFAULT 0`; `withMembership` **tenant satırını da** `FOR SHARE` okur; askıya alma (migration rolüyle `UPDATE tenants`) ve rol değişimi (üyelik satırı `UPDATE`) eşzamanlı yazmayı bekler.
- M8: `tenants` için `wms_app` `GRANT UPDATE (name)` yalnızca; `status`, `is_demo`, `slug` sütun yetkisi yok; DELETE yok.
- m1: `withMembership` yalnızca `app.current_tenant_id` kurar; `app.current_user_id` yalnızca `withUser`'da; kullanıcı kimliğine dayalı SELECT politikaları ek koşul `NULLIF(current_setting('app.current_tenant_id', true), '') IS NULL` taşır.
- B1 (ADR-016 §9): `SECURITY DEFINER` işlevi `identity_exclusive_to_tenant(target_user uuid) RETURNS boolean` — `SET search_path = pg_catalog, public`, çağıranın `app.current_tenant_id`'si boşsa `RAISE`, hedefin tüm `tenant_memberships` satırlarını `FOR SHARE` kilitler, tümü ACTIVE ve bu tenant'taysa ve tenant `is_demo=false` ise true; `REVOKE ALL … FROM PUBLIC`, `GRANT EXECUTE … TO wms_app`. Migration, işlev sahibinin RLS'i aşabildiğini (`rolsuper` veya `rolbypassrls`) doğrular; değilse `RAISE` (Neon karşılığı T-105 raporuna).

**İnceleme eki 2. tur (security-reviewer @ 0fdea50):**
- M-B: işlevlerin sahibi `wms_identity_probe` (T-101b); `SECURITY DEFINER`, `SET search_path = pg_catalog, pg_temp`, gövdede her nesne şema nitelikli (`public.tenant_memberships`, `pg_catalog.current_setting` …). Yalnızca bu role (`TO wms_identity_probe`) politikalar: `tenant_memberships`, `tenants`, `invitations` için `SELECT USING (true)` + `UPDATE USING (true) WITH CHECK (false)` (yalnızca kilit); yetkiler: bu tablolarda `SELECT` + tek sütunda `UPDATE`, `public.users` `SELECT` + `UPDATE (id)`, `admin_reset_grants` ve `verifications` `SELECT, DELETE`. Önceki "sahibi migration rolü, RLS'i aşabilmeli" maddesi **geçersiz**.
- M-B anlam: `wms_meta.identity_exclusive_to_tenant(target)` = bu tenant'ta ACTIVE üyelik VAR **ve** başka tenant'ta ACTIVE YOK; sıfır üyelik → false.
- M-A: `admin_reset_grants(id, user_id, issuing_tenant_id, verification_id, created_at, expires_at)` platform tablosu (`wms_app` INSERT, `wms_auth` SELECT); `tenant_memberships.user_id` → `public.users(id)` FK (eklemede `FOR KEY SHARE`); tekillik işlevi hedefin `users` satırını `FOR UPDATE` kilitler; `tenant_memberships` `AFTER INSERT OR UPDATE OF status` tetikleyicisi (yeni durum ACTIVE) `users` satırını `FOR KEY SHARE` kilitler ve kullanıcının `admin_reset_grants` + ilgili `verifications` satırlarını siler. `wms_meta.admin_reset_still_valid(verification_id)` (`wms_auth`'a EXECUTE): grant var, süresi geçmemiş ve `issuing_tenant_id` için tekillik hâlâ true.
- M-C: `invitations.delivered_via` (`EMAIL|SCREEN`, NOT NULL), `claim_id`, `claim_expires_at`; `wms_meta.invitation_for_account_creation(token_hash)` (`wms_auth`'a EXECUTE) yalnızca geçerli davetin `email_normalized` ve `delivered_via` değerini döndürür (başka sütun/tenant bilgisi yok).
- 2. tur m4: `tenants` `GRANT INSERT (id, slug, name, created_by_user_id, creation_request_id)` — `status`, `is_demo` hariç (varsayılanlar ACTIVE/false).
