# T-004: `docs/STACK.md` sürüm kilidi + `docs/MAP.md` ilk sürüm + `check-docs` doğrulayıcısı
**Faz:** 0 · **Ajan:** devops · **Bağımlılık:** T-002a–d (`int/faz0-iskelet` birleşmiş) · **Dal:** `feat/T-004-stack-map` → `int/faz0-docs`
**Amaç (tek cümle):** Kurulu sürümleri `docs/STACK.md`'ye tam sürüm olarak kilitlemek, `docs/MAP.md`'yi gerçek dizinlerle eşitlemek ve ikisinin gerçeklikle uyumunu makineyle doğrulamak.
**Okuma listesi (≤5):** `docs/STACK.md`, `docs/MAP.md`, `docs/adr/ADR-004.md §T-005 ile doldurulacak alanlar`, `docs/adr/ADR-005.md §Karar`, `pnpm ls -r --depth 0` + `docker-compose.yml` imaj etiketleri (komut çıktısı)
**Dokunulacak dosyalar (≤10):** `docs/STACK.md`, `docs/MAP.md`, `scripts/check-docs.mjs`, `scripts/check-docs.test.mjs`

**Yapılacaklar:**
1. STACK.md'ye "Kilitli sürümler" tablosu: `bileşen | paket/imaj | sürüm | kaynak (package.json yolu / compose servisi) | ADR`. Kapsam: Node.js (`engines`), pnpm (`packageManager`), TypeScript, ESLint, typescript-eslint, Vitest, Next.js, React, compose imajları (postgres, pgbouncer, minio, mailpit). Sürüm **kurulu olandan** okunur, tahmin edilmez (G-04).
2. Henüz kurulmamış/kararı açık satırlar sürüm yerine işaretle yazılır, uydurulmaz: Testcontainers → `T-005a`; Drizzle ve PostgreSQL sürücüsü → `T-005b (Q-03)` (bu kartlar T-004'ten önce birleşmişse kurulu sürüm yazılır, "Neon'da doğrulanacak: T-005d/e" notuyla); PostgreSQL ana sürümü (Neon) → `Q-05`; Neon pooler türü/sürümü → `Q-02`; prepared statement → `Q-04`; kuyruk kütüphanesi → `ADR-005 eki`; Tailwind/Shadcn/TanStack/next-intl/Zod → `ilk kullanan kart`.
3. Mevcut "Seçim (varsayılan öneri)" tablosu karar durumuna çekilir: ADR-001/003/004/005/006 seçilenleri (durum "önerildi" notuyla), reddedilenler kaldırılır; ADR-003/005 gerekçe bölümleri **değiştirilmez**.
4. MAP.md (≤60 satır): her satır `yol | durum (var / planlı: T-xxx) | açıklama`. Düzeltme: `apps/worker` "BullMQ işçileri" → "kalıcı worker süreci; kuyruk ADR-005 (Postgres kuyruğu), henüz iş yok". Eklenecek: `infra/`, `scripts/`, `.github/workflows/` (T-003 birleşmişse "var", değilse "planlı: T-003").
5. `scripts/check-docs.mjs` (yeni npm bağımlılığı yok; `node scripts/check-docs.mjs` ile çalışır): (a) STACK "Kilitli sürümler" tablosunda sürümü yazılı her satır, kaynak dosyadaki değerle **birebir** eşleşir (aralık `^`/`~` = hata); (b) MAP'te "var" işaretli her yol mevcuttur, "planlı" işaretliler mevcut değildir. Tek özet satırı `check-docs: stack OK|FAIL (<n> satır) · map OK|FAIL (<n> yol)`, FAIL → çıkış ≠ 0.
6. `check-docs.test.mjs`: ayrıştırıcıyı bellek içi örneklerle test eder (eşleşme, uyuşmazlık, aralık sürümü, eksik yol, planlı ama var olan yol).

**Kabul ölçütü:**
- `node scripts/check-docs.mjs` → `stack OK · map OK`, çıkış 0; `pnpm verify` → üç adım OK (yeni test dahil).
- Negatif kanıt: STACK'te bir sürüm bir yama numarası değiştirilince → `stack FAIL`, satır ve iki değer gösterilir; çıkış ≠ 0 (geri alınır; özet rapora).
- STACK/MAP'te doğrulanmamış hiçbir sürüm/yol "kesin" yazılmamış (Supervisor `git diff` ile kontrol eder).
**Kapsam dışı:** `check-docs`'u `pnpm check:all`/CI'a bağlamak (T-008), doğrudan bağımlılığın STACK'te eksik olmasını hata saymak (T-008'e öneri — rapora Bulgu), ADR dosyaları, Drizzle/sürücü satırlarının Neon sonucuyla kesinleştirilmesi (T-005e).
**Gerekli inceleme:** Risk matrisi "Diğer" → security-reviewer gerekmez; Supervisor diff okuması. Not: STACK'teki sürücü/ORM/pooler sürümleri `check:protected` kapsamına T-008'de girer.
