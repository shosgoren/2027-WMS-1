# T-102: Kimlik tabloları (platform) — `0002_identity` + Drizzle şeması + sapma testi
**Faz:** 1 · **Ajan:** db-engineer · **Bağımlılık:** T-101, T-101b, ADR-014 + ADR-016 kabul · **Dal:** `feat/T-102-identity-schema` → `int/faz1-sema`
**Amaç (tek cümle):** Better Auth 1.7.7'nin çekirdek + `twoFactor` + DB hız sınırı modellerini snake_case platform tablolarına (`users`, `sessions`, `accounts`, `verifications`, `two_factors`, `auth_rate_limits`, `security_events`) en dar `GRANT`'larla kuran migration'ı ve eşleşen Drizzle şemasını yazmak.
**Okuma listesi (≤5):** `docs/adr/ADR-014.md`, `docs/adr/ADR-016.md §1, §7`, `docs/adr/ADR-015.md §4–6`, Better Auth 1.7.7 "database / core schema" ve `twoFactor` şema belgesi (Context7 `/better-auth/better-auth`; alan listesi rapora kaynak bağlantısıyla, G-04), `packages/db/src/index.ts`
**Dokunulacak dosyalar (≤10):** `packages/db/migrations/0002_identity.up.sql`, `packages/db/migrations/0002_identity.down.sql`, `packages/db/src/schema/identity.ts`, `packages/db/src/schema/index.ts`, `packages/db/src/index.ts`, `packages/db/package.json`, `tests/integration/schema/drift.int.test.ts`, `tests/integration/schema/identity-grants.int.test.ts`

**Yapılacaklar:**
1. Alanlar Better Auth belgesindeki modellerden birebir (ad eşlemesi: tablo çoğul snake_case, sütun snake_case); kimlikler `uuid` (`gen_random_uuid()` varsayılanı; Better Auth kimlik üretim ayarı T-112'de bununla uyumlu yapılır). `users.email` küçük harfe normalize + `UNIQUE`. Belgede olmayan alan eklenmez; eksik bilgi → rapora "doğrulanamadı" + Q önerisi.
2. `security_events (id, occurred_at, user_id NULL, event_type, ip, user_agent, request_id, detail jsonb, created_xid xid8 DEFAULT pg_current_xact_id())` append-only: `wms_app` yalnızca `INSERT, SELECT`; `UPDATE/DELETE/TRUNCATE` tetikleyiciyle `RAISE`.
3. `GRANT`'lar tablo başına açık ve en dar (ör. `sessions`: SELECT/INSERT/UPDATE/DELETE; `security_events`: INSERT/SELECT). `wms_app` hiçbir tablonun sahibi değil. RLS yok (platform tablosu, ADR-016 §1) — bu bilinçli; dosya başında yorumla belirt.
4. `schema/identity.ts`: Drizzle `pgTable` tanımları (`drizzle-orm/pg-core`, sürücüsüz alt yol); `schema/index.ts` toplu dışa verim; `@wms/db` genel yüzeyine yalnızca **tipler** (tablo nesneleri değil) eklenir — tablo nesneleri yeni alt yol `@wms/db/internal/schema` (`package.json#exports`; mevcut lint kuralı `@wms/db/internal/…` alt yollarını zaten yasaklar) ile `packages/auth`'a (T-111 izin listesi, T-112) açılır; `client.ts`'e dokunulmaz.
5. `drift.int.test.ts`: migration'lar uygulanmış DB'de `information_schema.columns` ↔ `getTableConfig` (ad, tip, NULL'luk) birebir; sonraki şema kartları bu testi genişletir.
6. `identity-grants.int.test.ts`: `wms_app` ile `security_events` UPDATE/DELETE → hata; `wms_meta` erişimi → hata; down migration sonrası tablolar yok.

**İnceleme eki (security-reviewer @ 83b5bea):**
- M1 (ADR-014 §10): Better Auth tablolarında (`sessions`, `accounts`, `verifications`, `two_factors`, `auth_rate_limits`) yetki **yalnızca `wms_auth`**; `wms_app`: `users` üzerinde yalnızca `GRANT SELECT (id, name, email, email_verified)`, diğerlerinde hiçbir yetki; `wms_auth`: `security_events` INSERT, tenant tablolarında hiçbir yetki. Migration başında `wms_auth` için `0001`'deki rol denetiminin aynısı (yoksa/nitelik sapmışsa `RAISE`).
- m9: `auth_rate_limits` anahtar sütunu düz IP/e-posta değil SHA-256 özeti taşıyacak biçimde (`key_hash`) — Better Auth'un yazdığı biçim kurulu sürümde doğrulanır (T-112); uyumsuzsa rapora ve T-112 özel depolama kullanır.

**İnceleme eki 2. tur (security-reviewer @ 0fdea50):**
- m7: `sessions.mfa_verified_at timestamptz NULL` Better Auth çekirdek şemasına **bilinçli ek** (ADR-014 §12; `session.additionalFields`); dosya başı yorumunda ve drift testinde istisna olarak işaretlenir; `wms_auth` dışında yetki yok.

**İnceleme eki 3. tur (security-reviewer @ b400466):**
- m3: `wms_meta` kapalı kalır — Yapılacaklar 6'daki "`wms_meta` erişimi → hata" testi `wms_app` **ve** `wms_auth` için geçerlidir; kimlik yoklama işlevleri ayrı `wms_probe` şemasındadır (T-103).
- m7: `users.invitation_claim_id uuid NULL` — Better Auth çekirdek şemasına ikinci **bilinçli ek** (`user.additionalFields`; ADR-016 3. tur eki m7); dosya başı yorumunda ve drift testinde `mfa_verified_at` ile birlikte istisna. `wms_app`'in bu sütunda yetkisi yok (`GRANT SELECT (id, name, email, email_verified)` değişmez); `identity-grants.int.test.ts`: `wms_app` ile `users.invitation_claim_id` SELECT → yetki hatası.

**İnceleme eki 4. tur (security-reviewer delta @ c9195ef):**
- MAJOR-1 (ADR-014/ADR-016 4. tur eki): `wms_auth`'un `users` yetkisi `SELECT, INSERT, DELETE` + **sütun bazlı** `GRANT UPDATE (<Better Auth 1.7.7'nin güncellediği sütunlar>)`; `id` ve `invitation_claim_id` listede **yok** (tablo düzeyinde `UPDATE` verilmez). Liste Better Auth 1.7.7'nin `update-user`, `change-email`, 2FA ve doğrulama akışlarında yazdığı sütunlardan çıkarılır (paket bu kartta kurulu değilse Context7 belgesi + npm tarball kaynağı; kaynak rapora, G-04); eksik sütun T-112/T-112b int testlerinde yetki hatası olarak görünür ve bu migration'a değil yeni genişletme migration'ına eklenir. Better Auth tablolarının diğerlerinde (`sessions` dahil) `wms_auth` yetkisi değişmez. `admin_reset_grants`'te `wms_auth`'a yetki yok (T-103 4. tur eki). `identity-grants.int.test.ts`: `wms_auth` ile `UPDATE users SET invitation_claim_id = …` → yetki hatası; `UPDATE users SET id = …` → yetki hatası; `UPDATE users SET name = …` izinli; `wms_auth` ile `INSERT` (`invitation_claim_id` dahil) izinli.
