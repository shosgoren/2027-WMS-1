# T-102: Kimlik tabloları (platform) — `0002_identity` + Drizzle şeması + sapma testi
**Faz:** 1 · **Ajan:** db-engineer · **Bağımlılık:** T-101, ADR-014 + ADR-016 kabul · **Dal:** `feat/T-102-identity-schema` → `int/faz1-sema`
**Amaç (tek cümle):** Better Auth 1.7.7'nin çekirdek + `twoFactor` + DB hız sınırı modellerini snake_case platform tablolarına (`users`, `sessions`, `accounts`, `verifications`, `two_factors`, `auth_rate_limits`, `security_events`) en dar `GRANT`'larla kuran migration'ı ve eşleşen Drizzle şemasını yazmak.
**Okuma listesi (≤5):** `docs/adr/ADR-014.md`, `docs/adr/ADR-016.md §1, §7`, `docs/adr/ADR-015.md §4–6`, Better Auth 1.7.7 "database / core schema" ve `twoFactor` şema belgesi (Context7 `/better-auth/better-auth`; alan listesi rapora kaynak bağlantısıyla, G-04), `packages/db/src/index.ts`
**Dokunulacak dosyalar (≤10):** `packages/db/migrations/0002_identity.up.sql`, `packages/db/migrations/0002_identity.down.sql`, `packages/db/src/schema/identity.ts`, `packages/db/src/schema/index.ts`, `packages/db/src/index.ts`, `packages/db/package.json`, `tests/integration/schema/drift.int.test.ts`, `tests/integration/schema/identity-grants.int.test.ts`

**Yapılacaklar:**
1. Alanlar Better Auth belgesindeki modellerden birebir (ad eşlemesi: tablo çoğul snake_case, sütun snake_case); kimlikler `uuid` (`gen_random_uuid()` varsayılanı; Better Auth kimlik üretim ayarı T-112'de bununla uyumlu yapılır). `users.email` küçük harfe normalize + `UNIQUE`. Belgede olmayan alan eklenmez; eksik bilgi → rapora "doğrulanamadı" + Q önerisi.
2. `security_events (id, occurred_at, user_id NULL, event_type, ip, user_agent, request_id, detail jsonb, created_xid xid8 DEFAULT pg_current_xact_id())` append-only: `wms_app` yalnızca `INSERT, SELECT`; `UPDATE/DELETE/TRUNCATE` tetikleyiciyle `RAISE`.
3. `GRANT`'lar tablo başına açık ve en dar (ör. `sessions`: SELECT/INSERT/UPDATE/DELETE; `security_events`: INSERT/SELECT). `wms_app` hiçbir tablonun sahibi değil. RLS yok (platform tablosu, ADR-016 §1) — bu bilinçli; dosya başında yorumla belirt.
4. `schema/identity.ts`: Drizzle `pgTable` tanımları (`drizzle-orm/pg-core`, sürücüsüz alt yol); `schema/index.ts` toplu dışa verim; `@wms/db` genel yüzeyine yalnızca **tipler** (tablo nesneleri değil) eklenir — tablo nesneleri yeni alt yol `@wms/db/internal/schema` (`package.json#exports`; mevcut lint kuralı `@wms/db/internal/…` alt yollarını zaten yasaklar) ile `packages/auth`'a (T-111 izin listesi, T-112) açılır; `client.ts`'e dokunulmaz.
5. `drift.int.test.ts`: migration'lar uygulanmış DB'de `information_schema.columns` ↔ `getTableConfig` (ad, tip, NULL'luk) birebir; sonraki şema kartları bu testi genişletir.
6. `identity-grants.int.test.ts`: `wms_app` ile `security_events` UPDATE/DELETE → hata; `wms_meta` erişimi → hata; down migration sonrası tablolar yok.

**Kabul ölçütü:** `pnpm verify` OK; `pnpm test:int` → drift + grants + T-101 testleri PASS; ileri/geri/ileri döngüsü yeşil.
**Kapsam dışı:** Better Auth kurulumu (T-112), tenant tabloları (T-103), audit (T-107).
**Gerekli inceleme:** security-reviewer zorunlu (auth tabloları, GRANT); qa T-104. Paket `int/faz1-sema`.
