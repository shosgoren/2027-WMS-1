# T-242: `check:scope` çakışmalı birleştirmede MERGE_HEAD farkındalığı
**Faz:** 2 · **Ajan:** devops · **Bağımlılık:** — · **Dal:** `fix/T-242-scope-merge-head` → `int/faz2-bekci`
**Amaç (tek cümle):** Bir int dalına `origin/main` (ya da kart dalı) çakışmalı birleştirilirken pre-commit kancasındaki `check:scope`, birleştirilen tarafın kendi değişikliklerini kart dışı (OUT_OF_SCOPE) saymasın; kart dışı gerçek değişiklikler yine yakalansın.
**Okuma listesi (≤5):** `scripts/guards/scope.mjs` (~105-170), `scripts/guards/lib/git.mjs` (`changedFiles`, `mergeBase`), `scripts/guards/scope.test.mjs` (A–D senaryoları), `docs/agents/PROTOCOL.md` §3b
**Dokunulacak dosyalar (≤10):** `scripts/guards/scope.mjs`, `scripts/guards/lib/git.mjs`, `scripts/guards/scope.test.mjs`
**Bulgu (Supervisor, 2026-10-06):** çakışmalı `git merge origin/main` sırasında HEAD hâlâ eski uçta → `mergeBase(origin/main, HEAD)` eski taban; çalışma ağacı main'in yeni dosyalarını içerir → main'in dosyaları OUT_OF_SCOPE. Commit edilince (HEAD main'i içerir) sorun yok. Geçici çözüm: çözülmüş dosyayı önce ayrı commit + `merge -X ours`. `--no-verify` YASAK.
**Yapılacaklar:**
1. `.git/MERGE_HEAD` (worktree'de `git rev-parse --git-path MERGE_HEAD`) varsa değişiklik kümesi: çalışma ağacı ile "HEAD ve MERGE_HEAD'in her ikisinin de içerdiği" taban yerine, birleştirme sonucunun kart kapsamı açısından HEAD'e göre DEĞİL, hedef tabana göre doğru hesaplanması — tasarımı sen öner; kural: birleştirilen ucun (MERGE_HEAD) hedefin atası olduğu ya da hedefin kendisi olduğu durumda (`git merge-base --is-ancestor MERGE_HEAD origin/main`) taban `merge-base(target, MERGE_HEAD)` ile `HEAD` tabanından yeni olanı alınır.
2. Kart dalının (feat/T-xxx) birleştirilmesi sırasında da (int dalında kart merge'ü çakışırsa) kart kapsamı MERGE_HEAD dal adından çözülür (mevcut `mergedWorkBranches` kuralıyla, merge mesajı henüz yokken `MERGE_MSG`'den).
3. Sahtecilik testleri: MERGE_HEAD ilgisiz/atası olmayan bir commit'e işaret ederse (elle yazılmış dosya) gevşeme yok → mevcut sonuç; çakışmalı main birleştirmesi + ek kart dışı dosya değişikliği → yine FAIL (yalnız o dosya).
4. Mevcut tüm scope testleri değişmeden yeşil (G-11).
**Kabul ölçütü:** `pnpm verify` OK, `pnpm check:all` OK, `scope.test.mjs` yeni senaryolar (çakışmalı main merge → OK; + kart dışı dosya → FAIL; sahte MERGE_HEAD → gevşeme yok) yeşil; mutasyon: MERGE_HEAD dalı kaldırılınca yeni "OK" testi kırmızı.
**Kapsam dışı:** CI (non-local) modu, protected bekçisi.
**Gerekli inceleme:** security-reviewer (bekçi gevşemesi olmadığını doğrular).
