**Amaç (tek cümle):** `deploy-staging.yml`'e, Fly dağıtımından önce migration rolüyle (Neon sahip rolü, doğrudan bağlantı) `pnpm db:migrate` koşan ve başarısızlıkta dağıtımı durduran adımı eklemek (ADR-015 §7).
**Okuma listesi (≤5):** `.github/workflows/deploy-staging.yml` (tamamı), `docs/adr/ADR-015.md §3, §7`, `docs/tasks/T-010.md`, `scripts/neon-api.mjs` (T-105), `packages/db/src/migrate.ts` CLI girişi (T-101)

**Yapılacaklar:**
1. Yeni adımlar (Deploy'dan önce): pnpm kurulum (`pnpm/action-setup` tam SHA) → `pnpm install --frozen-lockfile --ignore-scripts` → `Migrate` adımı. `NEON_API_KEY` yalnızca `Migrate` adımının `env`'inde; `FLY_API_TOKEN` yalnızca `Deploy`'da kalır.
2. `deploy-migrate.mjs`: `neon-api.mjs` ile doğrudan sahip URI'sini alır (maskeli), `WMS_ENV=staging`, `DATABASE_URL_DIRECT` yalnızca alt sürece ortamla verilir; `pnpm db:migrate` çıktısından uygulanan sürüm listesini özetler (URL yok). Hata → iş kırmızı, Deploy adımı koşmaz.
3. Sıra notu (genişlet–taşı–daralt): migration önce, uygulama sonra; bir migration eski uygulama sürümünü bozacaksa (daraltma) bu kartın kapsamı dışında ayrı dağıtım gerekir — iş akışı başına yorum.
4. `deploy-smoke.mjs`: mevcut sağlık denetimine ek olarak `/api/health` yanıtında (T-129 sonrası) `db` alanı varsa `ok` olmalı; alan yoksa mevcut davranış (geriye uyumlu, sahte başarı yok — yalnızca var olanı denetler). Birim testleri güncellenir; mevcut testler azaltılmaz.
5. Kanıt yalnızca Actions'ta: `main`'e birleşme sonrası `deploy-staging` koşusu.
