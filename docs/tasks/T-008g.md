**protected: true** (beyan; onay değildir) — CI tanımı + kanca + bekçi betiği.
**Amaç (tek cümle):** Beş bekçiyi `pnpm check:all` altında toplayıp commit öncesi kancaya ve her PR'da koşan ayrı bir GitHub Actions iş akışına bağlamak ve AC-37'nin beş durumunun her birinin kırmızı ürettiğini `@AC-37` testiyle kanıtlamak.
**Okuma listesi (≤5):** `docs/agents/PROTOCOL.md §3b` + `§Onay kaynağı` (zorunlu durum kontrolleri), `docs/ACCEPTANCE.md AC-37`, `scripts/guards/cli.mjs` + `lib/output.mjs` + `lib/testkit.mjs`, `.github/workflows/ci.yml` (T-003; Node/pnpm kurulum ve SHA sabitli action adımlarını aynen kullan), GitHub Actions `pull_request` (`edited` türü) ve `permissions` belgesi (Context7/resmî — G-04)
**Dokunulacak dosyalar (≤10):** `scripts/guards/all.mjs`, `scripts/guards/cli.mjs`, `scripts/test-ac/cli.mjs`, `package.json` (kök; `check:all` + `prepare` satırları), `.githooks/pre-commit`, `.github/workflows/guards.yml` (yeni; T-003 dosyasına dokunulmaz), `tests/guards/ac-37.test.mjs`, `tests/.ac-baseline.json` (yalnızca `--update` artışı), `tests/guards/demo.test.mjs` (yalnızca gösterim dallarında; birleşmez)

**Yapılacaklar:**
1. `check:all`: scope, tests, ac-ratchet, protected, assertions sırayla, ilk hatada durmadan hepsini koşar; özet REPORT_TEMPLATE biçiminde `scope OK | tests OK | ac-ratchet OK | protected OK | assertions OK`; biri FAIL ise çıkış 1. T-004 `scripts/check-docs.mjs`'i buraya bırakmıştı: birleşmişse `check:all` sonuna ek adım olarak bağlanır (özette `docs OK|FAIL`); birleşmemişse rapora "bağlanmadı — T-004 bekleniyor". `check:pilot` `check:all`'a girmez (T-006 kullanıcı eylemi beklerken her PR'ı kilitlemesin); ayrı iş olarak koşar.
2. Kanca: bağımlılık eklemeden `.githooks/pre-commit` + `prepare` ile `git config core.hooksPath .githooks`. Kanca `check:all`'u `check:protected --local` ile koşar. Kanca atlanabilir (`--no-verify`); zorlama CI'dadır — kart ve raporda böyle yazılır.
3. `guards.yml`: tetikleyiciler `pull_request` (main ve `int/**` hedefli) (türler madde 5'te). İşler: `check-all`, `test-ac` (`pnpm test:ac --ci`), `check-pilot`. `permissions` en dar: `contents: read`, `pull-requests: read`. Tam git geçmişi (merge-base için). İş adları sabit — T-009b zorunlu kontrol olarak bunları seçer.
4. Sır yok: yalnızca yerleşik `GITHUB_TOKEN` (G-09).
5. **Önyükleme ve güven (ADR-012 rev.; bekciler-1 incelemesi M1/m3):**
   a. İş `check-all`: PR head ayrı dizine (`pr/`), taban `origin/<base.ref>` ayrı dizine (`base/`) checkout edilir. Taban dizininde `pnpm install --frozen-lockfile --ignore-scripts` (tabanın lockfile'ı) koşulur; PR dizininde **hiçbir** install/betik çalışmaz.
   b. Bekçi `node base/scripts/guards/cli.mjs all --root pr/` ile **doğrudan** çağrılır (`pnpm check:*` değil — PR'ın `.npmrc`/betikleri devreye girmesin). `scripts/guards/cli.mjs` ve `scripts/test-ac/cli.mjs`'e `--root <dizin>` desteği bu kartta eklenir (korunan değişiklik; kök, `REPO_ROOT` yerine bu değerden); testle: `--root` verilince taban dizini değil verilen dizin denetlenir.
   c. `test:ac` PR kodunu çalıştırmak zorunda olduğundan ayrı ve **sonraki** iş (`test-ac`, `needs: check-all`); PR dizininde install `--ignore-scripts` ile. Koşturucu tabandan çağrılır (`node base/scripts/test-ac/cli.mjs --ci --root pr/`); JSON raporu ve `.artifacts` çıktısı PR kodunun yazamayacağı `$RUNNER_TEMP/test-ac/` altındadır (`--out` desteği bu kartta; bekciler-1 3. inceleme MINOR 2).
   f. Çalışma zamanı atlama denetimi: `test-ac` işi vitest JSON raporunda `skipped`/`todo`/`pending` sayısı > 0 ise FAIL (karantina kaydı olanlar hariç, T-008e) — statik `check:tests`'in kaçırdığı `Reflect.get`, boş `describe.each`, koşulsuz erken `return` biçimleri için (MINOR 1).
   d. Önyükleme istisnası yalnızca `base.ref == main` **ve** `main`'de `scripts/guards/cli.mjs` yoksa geçerlidir; iş bunu "bootstrap" diye yazar. Başka her durumda tabanda bekçi yoksa FAIL.
   e. Tetikleyiciler `pull_request` türleri `opened, synchronize, reopened, edited` (gövde düzenlenince onay yeniden değerlendirilir); `push` (`main`, `int/**`).

**Kabul ölçütü:** `tests/guards/ac-37.test.mjs` (`@AC-37`) testkit deposunda gerçek CLI ile beş ayrı mutasyonu uygular: kart dışı dosya, `it.skip`, `@AC` testi silme, `expect(true)`, lint yapılandırmasında kural gevşetme (korunan yol). Her biri **ayrı ayrı** `check:all` (CI modu; `--local` değil) çıkış 1 ve çıktıda beklenen neden kodu + dosya yolu (`OUT_OF_SCOPE`, `SKIP`, `AC_TEST_REMOVED`, `CONSTANT_ASSERTION`, `PROTECTED_NO_APPROVAL`/`APPROVAL_UNVERIFIABLE`); temiz durum → 0. Her mutasyon yalnızca hedeflenen bekçiyi kırmalı (ör. lint mutasyonunda testkit kartı o yolu listeler, böylece `OUT_OF_SCOPE` karışmaz); test diğer dört bekçinin OK olduğunu da doğrular. `pnpm test:ac -- AC-37` PASS.
