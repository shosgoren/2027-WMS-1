# T-283: Yönetici kaynaklı parola sıfırlama — yetki denetimi + belirteç tüketimi + parola güncellemesi TEK transaction (dış inceleme bulgu 3; ADR-016 bilinen risk)
**Faz:** 3A (güvenilirlik) · **Ajan:** backend-dev · **Bağımlılık:** T-117b · **Dal:** `fix/T-283-yonetici-sifirlama-atomik` → `int/faz3a`
**Amaç (tek cümle):** Yönetici sıfırlama belirteciyle parola değişimi, hedefin üyeliği/yetkisi değişse bile eski yetkiyle tamamlanamasın: denetim, tüketim ve parola yazımı aynı `wms_auth` transaction'ında, hedef `users` satırı kilitli.

**Yapılacaklar:**
- Bugün: kanca grant'i kendi transaction'ında tüketip commit ediyor, Better Auth 1.7.7 parolayı ayrı yazıyor; arada hedef başka tenant'a katılırsa eski yetkiyle sıfırlama tamamlanabilir.
- Yönetici belirteçleri (`adm_…`) için Better Auth `/reset-password` yolunu kapat ve kendi uç/işlevini yaz: tek `wms_auth` transaction'ı → hedef `users` FOR UPDATE → grant geçerli + tüketilmemiş + ihraç eden tenant'ta hedef hâlâ üye ve yöneticinin yetki kapsamında (A-55 kuralları aynen) → grant tüket → parola özeti (mevcut `hashPassword`) yaz → hedefin tüm oturumlarını iptal → güvenlik olayı. Herhangi biri başarısızsa hiçbir şey yazılmaz. Kendi kendine (self-service) sıfırlama Better Auth yolunda kalır.
- Deterministik yarış testi: denetim ile yazım arasına üyelik değişikliği sokan test (ikinci bağlantı kilit bekler; advisory lock/ara kanca ile zamanlama), beklenen: sıfırlama reddedilir, parola değişmez, grant tüketilmez ya da tüketilir — kural ADR'ye yazılır.
- Parola politikası (uzunluk, sızmış parola kontrolü vb.) Better Auth yoluyla birebir aynı uygulanır (aynı işlev); hız sınırı aynı kova.
- ADR-016 "bilinen risk" bölümünü kapanış notuyla güncelle (durum satırı değişmez).
**Kabul ölçütü:** admin-reset-atomic int testi yeşil + mutasyon kanıtı (FOR UPDATE ya da yeniden denetim kaldırılınca kırmızı); tam `pnpm test:int` EXIT=0; `pnpm verify`; `pnpm check:all`.
**Kapsam dışı:** Better Auth sürüm yükseltmesi; self-service sıfırlama akışı.
