# T-010: Fly.io staging dağıtım hattı (web + worker, `fra`)
**Faz:** 0 · **Ajan:** devops · **Bağımlılık:** T-002b/c, T-003; kullanıcı eylemi tamam (U-02: `FLY_API_TOKEN` repo sırrı) · **Dal:** `feat/T-010-fly-staging` → `int/faz0-deploy`
**protected: true** (beyan) — `.github/workflows/**`.
**Amaç (tek cümle):** `main`'e her birleşmede tek Docker imajını Fly.io'da `etkin-wms-staging` uygulamasına (süreç grupları `web`, `worker`; bölge `fra`) dağıtan ve `/api/health` ile doğrulayan GitHub Actions hattını kurmak (ADR-013).
**Okuma listesi (≤5):** `docs/adr/ADR-013.md`, `docs/adr/ADR-001.md §Karar`, `docs/tasks/T-002b.md`, `docs/tasks/T-002c.md` (+ T-002c bulgusu: `tsconfig.build.json`), Fly.io belgesi (fly.toml `processes`, `flyctl deploy --remote-only`, `superfly/flyctl-actions` — Context7/resmî, G-04)
**Dokunulacak dosyalar (≤10):** `Dockerfile`, `.dockerignore`, `fly.staging.toml`, `.github/workflows/deploy-staging.yml`, `apps/web/next.config.ts` (yalnızca `output: "standalone"`), `apps/worker/tsconfig.build.json`, `apps/worker/package.json` (yalnızca `build` betiği), `scripts/deploy-smoke.mjs`, `scripts/deploy-smoke.test.mjs`

**Yapılacaklar:**
1. `Dockerfile` çok aşamalı: pnpm `--frozen-lockfile --ignore-scripts` (`npm_config_ignore_pnpmfile=true`), web `next build` standalone, worker `tsc -p tsconfig.build.json` (test dosyaları dışarıda); çalışma imajı Node 24 slim, root olmayan kullanıcı, yalnızca üretim çıktıları. Taban imaj etiket + digest.
2. `fly.staging.toml`: `app = "etkin-wms-staging"`, `primary_region = "fra"`, `[processes] web = "node apps/web/server.js"` (standalone yolu derlemeden doğrulanır), `worker = "node apps/worker/dist/main.js"`; `http_service` yalnızca `web`, iç port, `force_https`, `/api/health` kontrolü; en küçük makine (web shared-cpu-1x 512MB, worker shared-cpu-1x 256MB), `auto_stop_machines` web için açık, worker için kapalı (kalıcı süreç). Ölçekleme yok.
3. `deploy-staging.yml`: tetikleyici `push` (`main`) + `workflow_dispatch`; `permissions: contents: read`; `concurrency` (iptal yok — yarım dağıtım bırakılmaz); action'lar tam SHA; `FLY_API_TOKEN` yalnızca dağıtım adımının `env`'inde. Uygulama yoksa `flyctl apps create etkin-wms-staging --org <token org>` (idempotent; varsa geç). `flyctl deploy --remote-only -c fly.staging.toml`.
4. `deploy-smoke.mjs`: dağıtım sonrası `https://etkin-wms-staging.fly.dev/api/health` → 200 + `{status:"ok"}` (yeniden deneme + zaman aşımı); `flyctl status` çıktısından `worker` sürecinin `started` olduğu doğrulanır. Birim testleri (sahte fetch/çıktı) `deploy-smoke.test.mjs`.
5. Sır yok: DB/S3/e-posta henüz bağlanmaz (ilk migration ve dosya kartlarında); uygulama bunlar olmadan ayağa kalkmalı.
6. Ağ notu: ajan ortamından fly.io'ya erişim yok — kanıt yalnızca Actions koşusundan (GitHub MCP ile log/özet). Yerelde: `docker build` + konteynerde `/api/health` ve worker başlangıç log'u.

**Kabul ölçütü:** yerelde `docker build` başarılı ve konteyner `/api/health` 200; PR'da CI yeşil; `main`'e birleşince (veya `workflow_dispatch` ile) `deploy-staging` koşusu yeşil, smoke çıktısı ve `https://etkin-wms-staging.fly.dev/api/health` 200 (koşu bağlantısı rapora). `pnpm verify` OK.
**Kapsam dışı:** prod uygulaması (Faz 4P), Neon/Tigris/Resend bağlantısı, alan adı, migration adımı.
**Gerekli inceleme:** **security-reviewer zorunlu** (sır kapsamı, imaj, iş akışı izinleri).
