# T-002d: Yerel altyapı — docker compose (postgres, PgBouncer transaction mode, minio, mailpit) + `.env.example`
**Faz:** 0 · **Ajan:** devops · **Bağımlılık:** T-002a (dosya kümesi ayrık → T-002b/c ile paralel) · **Dal:** `feat/T-002d-compose` → `int/faz0-iskelet`
**Amaç (tek cümle):** `docker compose up -d --wait` ile postgres, transaction-mode PgBouncer, MinIO ve Mailpit'i sağlıklı ayağa kaldırmak ve bunu tek duman komutuyla kanıtlamak.
**Okuma listesi (≤5):** `docs/spec/14-reliability-ops.md`, `docs/spec/02-tenancy-auth.md §Pooler uyumluluğu`, `docs/adr/ADR-004.md §Karar, §T-005 ile doldurulacak alanlar`, `docs/adr/ADR-006.md §Karar`, kurulu PgBouncer imajının yapılandırma belgesi (G-04)
**Dokunulacak dosyalar (≤10):** `docker-compose.yml`, `.env.example`, `infra/pgbouncer/pgbouncer.ini`, `infra/postgres/init/01-roles.sh`, `scripts/compose-smoke.mjs`, `package.json`

**Yapılacaklar:**
1. Servisler: `postgres`, `pgbouncer`, `minio`, `mailpit`. **Redis yok** (ADR-005). Her imaj tam sürüm etiketiyle (`latest` yasak); her servis için `healthcheck`.
2. PostgreSQL ana sürümü **Q-05**'e bağlı: Neon projesindeki sürüm biliniyorsa o; değilse Neon belgelerinde desteklenen en yeni ana sürüm (kaynak bağlantısı rapora) ve rapora "Q-05 cevabıyla eşitlenecek; T-005d doğrular" notu. Uydurma sürüm yok.
3. PgBouncer: `pool_mode = transaction`; `default_pool_size` ortam değişkeniyle (AC-05 için 1–2'ye düşürülebilmeli); PgBouncer sürümü ve `max_prepared_statements` değeri **Q-02/Q-04**'e eşitlenecek alanlardır → ortam değişkeni/ini değeri, seçilen varsayılan ve gerekçesi rapora. `infra/postgres/init/01-roles.sh` yalnızca **yerel/CI** için `wms_app` rolünü oluşturur: `LOGIN NOSUPERUSER NOBYPASSRLS NOCREATEDB NOCREATEROLE`, parola `WMS_APP_PASSWORD`'dan (I-03); tablo sahipliği yok. PgBouncer `wms_app` ile kimlik doğrular (yöntem: `auth_query` veya userlist — seçim ve gerekçe rapora). Neon'daki karşılığı Q-06 / T-005d.
4. Portlar: uygulama → PgBouncer; migration/doğrudan → postgres. `.env.example`: `POSTGRES_USER=wms_migrator` (yerel/CI'da migration rolü = konteyner bootstrap kullanıcısı; Neon karşılığı Q-06), `DATABASE_URL` (`wms_app`, pooler üzerinden), `DATABASE_URL_DIRECT` (`wms_migrator`, doğrudan), `WMS_APP_PASSWORD`. Neon'da aynı adlar kullanılır; gerçek değerler yalnızca `.env`/CI sırrında (G-09). `.env.example` yalnızca yerel yer tutucu içerir.
5. MinIO: özel bucket adı `.env.example`'da; Mailpit: SMTP + UI portları.
6. `scripts/compose-smoke.mjs` (+ kök `package.json`'a `infra:smoke`): **yeni npm bağımlılığı eklenmez** (`pnpm-lock.yaml`'a dokunulmaz → T-002b/c ile paralel çalışabilir); `psql` postgres konteynerinden `docker compose exec` ile çalıştırılır. PgBouncer üzerinden `wms_app` ile `SELECT 1`; `pg_roles`'ta `wms_app` için `rolsuper = false`, `rolbypassrls = false`; PgBouncer yönetim konsolunda `SHOW CONFIG` → `pool_mode = transaction`; MinIO sağlık uç noktası 200; Mailpit UI 200. Tek özet satırı: `infra: pg OK · pgbouncer(transaction) OK · minio OK · mailpit OK`, FAIL → çıkış ≠ 0.

**Kabul ölçütü:**
- Temiz ortamda `cp .env.example .env && docker compose up -d --wait && pnpm infra:smoke` → özet satırında dört OK, çıkış 0.
- Negatif kanıt: `pool_mode = session` yapılınca `infra:smoke` → `pgbouncer FAIL`, çıkış ≠ 0 (geri alınır; iki çıktı özeti rapora).
- `pnpm verify` → üç adım OK; `git ls-files` `.env` içermez.
**Kapsam dışı:** Rol/RLS fikstürü (T-005a), `withTenant` (T-005b), CI'da compose (T-003), Neon bağlantısı (T-005b), kuyruk/dosya adaptörleri.
**Gerekli inceleme:** Risk matrisi: DB rolü (I-03) + sır taşıyan yapılandırma → **security-reviewer zorunlu** (rol öznitelikleri, yer tutucular); qa: rol izolasyonu T-005c'nin bağımsız testlerinde doğrulanır, bu kartta uygulayıcının duman testi yeterli.
