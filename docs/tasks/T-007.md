# T-007: `pnpm test:ac` — faz kapısı koşturucusu + `ACCEPTANCE.conditions.json`
**Faz:** 0 · **Ajan:** devops · **Bağımlılık:** T-002a (kök `package.json`, Vitest; betikler `.mjs` + JSDoc), Playwright koşturma yolu yalnızca kurulduğunda etkin (Faz 1; kurulu değilse Playwright etiketi bulunursa hata); T-006 yalnızca PILOT anahtar adları için (kartı yeterli, dosyası gerekmez) · **Dal:** `feat/T-007-test-ac` → `int/faz0-bekciler-1`
**protected: true** (beyan; onay değildir) — koşturucu kapı aracıdır; `docs/ACCEPTANCE.conditions.json` §Onay kaynağı listesindedir.
**Amaç (tek cümle):** `pnpm test:ac --phase <N>` ve `pnpm test:ac -- AC-xx` ile ACCEPTANCE.md'deki AC'leri `@AC-xx` etiketli testlere eşleyip koşturan, eksik testi ve belirsiz koşulu hata sayan (fail-closed) bir koşturucu yazmak.
**Okuma listesi (≤5):** `docs/PHASES.md` (giriş paragrafı: Kapı kuralı), `docs/ACCEPTANCE.md` (tablo biçimi + §Koşullu), `docs/tasks/T-006.md` (PILOT `key` ve enum listesi), `docs/STACK.md` (Test satırı), kurulu Vitest/Playwright tip tanımları (reporter ve ad filtresi API'si — G-04, tahmin yok)
**Dokunulacak dosyalar (≤10):** `scripts/test-ac/cli.mjs`, `scripts/test-ac/acceptance.mjs` (ACCEPTANCE.md ayrıştırıcı), `scripts/test-ac/conditions.mjs`, `scripts/lib/pilot.mjs` (PILOT.md tablo ayrıştırıcısı; T-008f yeniden kullanır), `scripts/test-ac/collect.mjs` (etiket toplama; T-008d yeniden kullanır), `scripts/test-ac/run.mjs`, `scripts/test-ac/test-ac.test.mjs` (fixture'lar test içinde tanımlanır, geçici dizinde üretilir; ayrı fixture klasörü yok — paket ≤30 dosya), `docs/ACCEPTANCE.conditions.json`, `package.json` (kök; yalnızca `test:ac` script satırı)

**Yapılacaklar:**
1. ACCEPTANCE.md iki tabloyu ayrıştır: `ID | Faz` (+ koşullu tabloda `Koşul`). Faz değerleri dize (`0,1,2,3A,3B,4P,4S,5,6,7`); `3A (koşul yoksa 3B)` → `{phase:'3A', fallbackPhase:'3B'}`. Tanınmayan satır/faz = hata (sessiz atlama yok).
2. `ACCEPTANCE.conditions.json`: `currentGatePhase: "0"` (kapısı değerlendirilen faz; `--phase` verilmezse varsayılan; T-008e karantina kuralı 3 bunu okur; değişimi §Onay kaynağına tabi) + her koşullu AC için `{source: "PILOT"|"FACT", key, anyOf[], phase, fallbackPhase?}` + `facts` (`adr005_separate_broker: false`, kaynak T-001b varsayılanı / ADR-005 "önerildi"; ADR-005 değişirse bu dosya §Onay kaynağıyla değişir). PILOT anahtarları: AC-34 `tracking_mode.*` ∈ LOT/LOT_AND_SERIAL · AC-42 `tracking_mode.*` ∈ SERIAL/LOT_AND_SERIAL · AC-41 `expiry_tracking`=YES · AC-38 `handling_unit_mode` ∈ TRACKED/MIXED. Kaynak dosya/anahtar yoksa, istenen faz koşullu AC'yi içeriyorsa = hata.
3. Etiket toplama: test başlığında `@AC-\d+` (statik tarama, `tests/**`, `packages/**`, `apps/**`, `scripts/**`; `node_modules` hariç). Koşturma: Vitest ve Playwright ad filtresiyle; JSON raporundan her AC için **gerçekten koşmuş** test sayısı okunur — 0 veya atlanmış = hata.
4. İki mod. **Kapı modu** `--phase N`: yukarıdaki katı kural. **CI modu** `--ci` (PR'larda zorunlu durum kontrolü): mevcut her `@AC` testi koşar ve geçmeli; `NO_TEST` yalnızca `ACCEPTANCE.conditions.json` → `passedGates` (başlangıç `[]`) içindeki fazlar için hata, diğerlerinde raporlanır. Gerekçe: katı mod zorunlu kontrol olursa Faz 0 AC testleri yazılmadan hiçbir PR birleşemez (kilitlenme). Bu yorum Supervisor onayı/ADR ister (rapora "ADR adayı" yaz).
5. Çıktı: AC başına tek satır `PASS | FAIL | NO_TEST | SKIPPED(koşul: …) | CONDITION_UNKNOWN`; ayrıntılı döküm `.artifacts/test-ac/<faz>.json`. Herhangi biri PASS/SKIPPED değilse çıkış kodu ≠ 0.
6. Karantina koşturucuyu etkilemez: kapı AC testi her durumda koşar ve sonucu sayılır (karantina mantığı T-008e). **Korunan dosya ilk oluşturma akışı:** `check:protected` henüz CI'da yok (T-008c/g) → PROTOCOL §Onay kaynağı geçici akışı: paket PR'ı `int/faz0-bekciler-1 → main` küçük tutulur; Supervisor kullanıcıya PR bağlantısıyla tek mesaj (ne, neden, risk); kullanıcı GitHub'da **son commit'i** onaylar ve **kendisi birleştirir**; ajan birleştirmez. T-009a önce bittiyse CODEOWNERS zorunlu incelemesi bunu GitHub'da da zorlar; bitmediyse yalnızca süreçle korunur (ADR-012 bilinen risk). Rapordaki "KORUNAN DOSYA DEĞİŞİKLİĞİ" satırı dosyalar + PR bağlantısı; bağlantı yoksa DONE olamaz.

**Kabul ölçütü:** `pnpm vitest run scripts/test-ac` yeşil ve şu fixture senaryolarını içerir: etiketsiz AC → NO_TEST + çıkış 1 · etiketli geçen → 0 · etiketli kalan → 1 · `skip` edilmiş etiketli test → hata · koşul doğru → dahil · koşul yanlış → SKIPPED + koşul metni · `3A (koşul yoksa 3B)` koşul yanlış + `--phase 3B` → dahil · PILOT dosyası yok + `--phase 3A` → CONDITION_UNKNOWN + çıkış 1 · bozuk satır → hata · `-- AC-05` yalnızca onu koşar · `--ci` + `passedGates:[]` + etiketsiz AC → çıkış 0 ve NO_TEST raporlanır · `--ci` + `passedGates:["0"]` + etiketsiz Faz 0 AC'si → çıkış 1.
