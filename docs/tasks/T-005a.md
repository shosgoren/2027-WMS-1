# T-005a: `pnpm test:int` koşum altyapısı (PgBouncer arkasında) + CI `int` işi
**Faz:** 0 · **Ajan:** devops · **Bağımlılık:** T-002d, T-003 (`ci.yml` birleşmiş) · **Dal:** `feat/T-005a-int-harness` → `int/faz0-pooler`
**Amaç (tek cümle):** Entegrasyon testlerini her zaman transaction-mode PgBouncer arkasında (`compose` hedefi) veya açıkça seçilince Neon'da (`neon` hedefi) koşturan, atlama yapmayan `pnpm test:int` komutunu kurup CI'a bağlamak.
**Okuma listesi (≤5):** `docs/spec/02-tenancy-auth.md §Pooler uyumluluğu`, `docs/adr/ADR-004.md §Sonuçlar ve riskler`, `docs/tasks/T-002d.md`, `docs/tasks/T-003.md`, kurulu `testcontainers` sürümünün Docker Compose modülü belgesi (Context7, G-04)
**Dokunulacak dosyalar (≤10):** `package.json`, `pnpm-lock.yaml`, `vitest.int.config.ts`, `tests/integration/harness/env.ts`, `tests/integration/harness/env.int.test.ts`, `tests/integration/harness/global-setup.ts`, `tests/integration/harness/harness.int.test.ts`, `.github/workflows/ci.yml`
**protected: true** — `ci.yml` ve test yapılandırması korunan dosyadır; kullanıcı onaylı PR (ADR-012 geçici dönem: kullanıcı birleştirir).

**Yapılacaklar:**
1. `testcontainers` tam sürüm (`-E`), lisans/bakım rapora. `vitest.int.config.ts`: yalnızca `**/*.int.test.ts`; `globalSetup`.
2. `env.ts`: `WMS_INT_TARGET` = `compose` (varsayılan) | `neon`. `neon` için `DATABASE_URL` (uygulama rolü, pooler) ve `DATABASE_URL_DIRECT` (migration rolü, doğrudan) **zorunlu**; eksikse açık hatayla düşer (atlama yok — `check:tests` kuralı). URL'ler log'a/hata mesajına **yazılmaz**, yalnızca maskeli host (G-09). Yalnızca teste özgü isteğe bağlı geçersiz kılma: `INT_DB_PREPARE` (`true|false`; yoksa üretim ayarı kullanılır — T-005d'nin prepared statement ölçümü için).
3. `global-setup.ts` (`compose`): repodaki `docker-compose.yml`'den yalnızca `postgres` + `pgbouncer` servislerini Testcontainers Compose modülüyle kaldırır (tek yapılandırma kaynağı; ini/imaj kopyalanmaz), bağlantı URL'lerini testlere ortam üzerinden verir, sonunda indirir. PgBouncer `default_pool_size` testte `INT_PGBOUNCER_POOL_SIZE` ile (varsayılan 2) ayarlanır.
4. `harness.int.test.ts` (her iki hedefte de koşar): pooler URL'siyle `current_user` = uygulama rolü; bu rol için `rolsuper = false`, `rolbypassrls = false` ve `pg_auth_members`'ta hiçbir role üyeliği yok (sahip rol yetkisini miras almasın — I-03); transaction dışında `current_setting('app.current_tenant_id', true)` boş/NULL. `compose` hedefinde ek olarak: PgBouncer yönetim konsolunda `pool_mode = transaction`.
5. `env.int.test.ts`: hedef ayrıştırma; `neon` + eksik değişken → hata (mesajda URL yok).
6. Kök `package.json`: `test:int` → `vitest run -c vitest.int.config.ts`; `test:int:neon` → aynı komut `WMS_INT_TARGET=neon` ile.
7. `ci.yml`'e `int` işi: `pnpm test:int` (compose hedefi, sırsız). T-003'ün iş adları ve diğer adımlar değişmez. Neon hedefi CI'a **eklenmez**.

**Kabul ölçütü:**
- Yerelde `pnpm test:int` → harness testleri PASS (özet satırı rapora; tam döküm `.artifacts/test-int/`); `pnpm verify` → üç adım OK.
- Negatif kanıt: `WMS_INT_TARGET=neon` ve değişkenler boş → çıkış ≠ 0, mesajda "missing DATABASE_URL" benzeri, URL yok. `pgbouncer.ini`'de geçici `pool_mode = session` → harness `pool_mode` testi FAIL (geri alınır).
- PR'da CI `int` işi yeşil (koşu bağlantısı rapora).
**Kapsam dışı:** `packages/db`, `withTenant`, RLS fikstürü (T-005b); AC testleri (T-005c); Neon koşusu (T-005d).
**Gerekli inceleme:** Risk matrisi: tenant izolasyonu altyapısı + sır işleme + CI → **security-reviewer zorunlu**; bağımsız qa: T-005c paketi içinde. Paket `int/faz0-pooler` (T-005a→b→c) tek inceleme.
