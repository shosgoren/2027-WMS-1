# T-008a: Bekçi altyapısı + `check:scope`
**Faz:** 0 · **Ajan:** devops · **Bağımlılık:** T-002a (kök araç zinciri; betikler `.mjs` + JSDoc, `checkJs` — T-002a §4), T-007 (ikisi de kök `package.json`'a yazar → seri) · **Dal:** `feat/T-008a-guard-core-scope` → `int/faz0-bekciler-1`
**protected: true** (beyan; onay değildir) — bekçi betikleri korunan dosyadır (PROTOCOL §3b).
**Amaç (tek cümle):** Tüm bekçilerin kullanacağı ortak git/kart/çıktı yardımcılarını ve daldaki değişen dosyaları kartın "Dokunulacak dosyalar" listesiyle karşılaştıran `pnpm check:scope`'u yazmak.
**Okuma listesi (≤5):** `docs/agents/PROTOCOL.md §3b` (tablo), `docs/agents/PROTOCOL.md §2 adım 5` (inceleme paketi, `int/` dalları), `docs/tasks/_TEMPLATE.md`, `docs/tasks/T-007.md` (dosya listesi biçimi örneği), `CLAUDE.md` (G-08 dal adları, G-10)
**Dokunulacak dosyalar (≤10):** `scripts/guards/lib/git.mjs`, `scripts/guards/lib/cards.mjs`, `scripts/guards/lib/output.mjs`, `scripts/guards/cli.mjs`, `scripts/guards/scope.mjs`, `scripts/guards/scope.test.mjs`, `scripts/guards/lib/git.test.mjs`, `scripts/guards/lib/testkit.mjs` (geçici dizinde `git init` + dosya/commit/dal kurulumu; tüm bekçi testleri kullanır, ayrı fixture klasörü yok), `package.json` (kök; yalnızca `check:scope|tests|ac-ratchet|protected|assertions|pilot` satırları → `scripts/guards/cli.mjs <ad>`)

**Yapılacaklar:**
1. `lib/git.mjs`: hedef dal (varsayılan `origin/main`) ile merge-base; değişen dosyalar (ekleme/silme/yeniden adlandırma dahil — ad değişikliğinde eski ve yeni yol); bir dosyanın `main`'deki içeriği. Testler geçici dizinde `git init` ile gerçek depo kurar (sahte git çıktısı yok).
2. `lib/output.mjs`: tek biçim `[check:<ad>] FAIL <NEDEN_KODU> <dosya> — <açıklama>`; özet `check:<ad> OK|FAIL (n)`; ayrıntı `.artifacts/guards/<ad>.json`. AC-37 "mesaj nedeni ve dosyayı gösterir" buna dayanır.
3. `lib/cards.mjs`: dal adından kart (`feat|fix/T-xxx[a-z]?-…` → `docs/tasks/T-xxx.md`); `int/*` dalında kapsam = merge-base..HEAD arasındaki birleştirilmiş `feat|fix/T-xxx` dallarının kartlarının birleşimi; kart bulunamazsa veya dal adı kalıba uymazsa **hata** (fail-closed). "Dokunulacak dosyalar" satırındaki backtick içindeki yollar glob olarak okunur; parantez içi açıklamalar yok sayılır.
4. `scope.mjs`: değişen her dosya en az bir glob ile eşleşmeli; kartın kendisi örtük izinlidir; başka örtük izin yok. Kartın dosya listesi dalda değiştiyse çıktıya `SCOPE_CARD_CHANGED` uyarısı (Supervisor §2 adım 4'te okur).
5. `cli.mjs`: altı bekçi adını modüle yönlendirir; henüz yazılmamış bekçi `FAIL NOT_IMPLEMENTED` + çıkış 1 döner (sahte OK yok, G-07). Böylece T-008b–f kök `package.json`'a dokunmaz ve paralel çalışabilir (`check:all` + `prepare` satırları T-008g'de). Betikler `node` ile doğrudan çalışır (`.mjs`, ek çalıştırıcı yok — T-002a/T-002c ile aynı yaklaşım); tipler JSDoc, kök `tsc` `checkJs` ile denetler.
6. Bağımlılık eklenmez (glob için Node yerleşik API'si — kurulu Node sürümünde varlığını `@types/node`'dan doğrula, G-04; yoksa basit desen eşleyici yaz ve test et).
7. Korunan dosya ilk oluşturma akışı T-007 Yapılacaklar 6 ile aynı (paket PR'ı, kullanıcı son commit'i onaylar ve kendisi birleştirir; T-009a öncesi bilinen risk).

**Kabul ölçütü:** `pnpm vitest run scripts/guards` yeşil; fixture senaryoları: kart içi değişiklik → OK · kart dışı dosya → FAIL `OUT_OF_SCOPE <yol>` · kart dışına yeniden adlandırma → FAIL · kartı olmayan dal → FAIL `CARD_NOT_FOUND` · `int/` dalında iki kartın birleşimi → OK, üçüncü kartın dosyası → FAIL · kart listesi dalda genişletilmiş → OK + `SCOPE_CARD_CHANGED`. Bu kartın kendi dalında `pnpm check:scope` → OK (çıktı raporda). `pnpm verify` özet satırı raporda.
