# T-112: `packages/auth` — Better Auth kurulumu (e-posta+parola, Argon2id, DB oturumu, TOTP, hız sınırı) + `/api/auth` uç noktası
**Faz:** 1 · **Ajan:** backend-dev · **Bağımlılık:** T-102, T-107, T-111 · **Dal:** `feat/T-112-auth-core` → `int/faz1-auth`
**Amaç (tek cümle):** ADR-014 kararlarını uygulayan Better Auth sunucu yapılandırmasını T-102 tablolarına bağlamak ve kimlik olaylarını `security_events`'e yazan, oturumu/yeniden doğrulamayı soyutlayan dar bir `@wms/auth` yüzeyi sunmak.
**Okuma listesi (≤5):** `docs/adr/ADR-014.md`, `docs/OPEN_QUESTIONS.md A-37…A-43, A-50`, `packages/db/src/schema/identity.ts`, Better Auth 1.7.7 belgesi: Drizzle adapter + `modelName`/`fields` eşlemesi, `session`, `rateLimit` (database storage), `twoFactor`, `emailAndPassword.password`, `toNextJsHandler`/`nextCookies`, kimlik üretimi (Context7 `/better-auth/better-auth`; kurulu tip tanımlarıyla doğrula, G-04), `packages/db/src/audit.ts` (`recordSecurityEvent`)
**Dokunulacak dosyalar (≤10):** `packages/auth/package.json`, `packages/auth/tsconfig.json`, `packages/auth/src/index.ts`, `packages/auth/src/password.ts`, `packages/auth/src/auth.test.ts`, `apps/web/app/api/auth/*/route.ts`, `apps/web/package.json`, `tests/integration/auth/auth-core.int.test.ts`, `pnpm-lock.yaml`, `docs/STACK.md` (Next dinamik segmentleri `[slug]`, `[token]`, `[...all]` kart globunda `*` ile yazılır: `check:scope` `path.matchesGlob` köşeli parantezi karakter sınıfı sayar)

**Yapılacaklar:**
1. Bağımlılıklar tam sürüm: `better-auth` 1.7.7, `@node-rs/argon2` 2.2.1 (sürümler kurulumda npm'den yeniden doğrulanır; değişmişse rapora); `STACK.md`'ye kilit satırları (ADR-014).
2. `createAuth({ client, env })` (`index.ts`): Drizzle bağdaştırıcısı ham istemciyle (`@wms/db/internal`, T-111 izni) ve `@wms/db/internal/schema` tablolarıyla; tablo/alan eşlemesi T-102 adlarına; kimlikler `uuid` (T-102 ile uyumlu ayar — kurulu tiplerden doğrula). `emailAndPassword` (A-41 uzunlukları; `password.hash/verify` = Argon2id `password.ts`), `session` (A-39; `cookieCache` kapalı), `rateLimit` DB depolamalı + uç noktaya özel kurallar (A-41), `twoFactor({ issuer: "Etkin WMS" })`, `trustedOrigins: [BETTER_AUTH_URL]`, `nextCookies()` son eklenti. Sosyal sağlayıcı yapılandırması `AUTH_SOCIAL_ENABLED !== "true"` iken **eklenmez** (A-37). E-posta doğrulaması `AUTH_REQUIRE_EMAIL_VERIFICATION` bayrağı (A-50). Eksik zorunlu ortam değişkeni (`BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `DATABASE_URL`) → sunucu çalışma anında (ilk kullanımda) açık hata (G-07); `next build` ve Docker derlemesi bu değişkenler olmadan geçmelidir (staging sırları T-105 ile önceden yazılır).
3. Dar yüzey: `getPrincipal(headers) → { userId, sessionId, authenticatedAt, mfaVerified } | null`, `requireRecentAuth(principal, maxAgeSec)` (A-39 penceresi), `revokeUserSessions(userId)`; Better Auth nesnesi paket dışına yalnızca route handler için verilir.
4. Olaylar: giriş başarılı/başarısız, çıkış, parola değişimi/sıfırlama, 2FA aç/kapa → `recordSecurityEvent` (Better Auth `hooks`/`databaseHooks` — hangisi kurulu sürümde destekleniyorsa; parola/belirteç değeri yazılmaz).
5. Parola sıfırlama e-postası gönderimi bu kartta **bağlanmaz**: `sendResetPassword` kancası T-116/T-117 gelene kadar `MAIL_DELIVERY_DISABLED` hatası fırlatır ve UI'da "yöneticinden sıfırlama bağlantısı iste" yolu gösterilir (A-42; sahte başarı yok).
6. Oturum belirtecinin DB'de saklanma biçimini (düz/özet) kurulu kaynaktan doğrula → rapora (ADR-014 risk satırı).
7. `auth.test.ts` (unit): Argon2id parametreleri, ortam doğrulaması, bayrak kapalıyken sosyal sağlayıcı yok. `auth-core.int.test.ts` (compose + migration'lar, `wms_app`): kayıt → giriş → oturumlu istek → çıkış → aynı çerezle istek `null`; `revokeUserSessions` sonrası `null`; yanlış parola × eşik → hız sınırı; TOTP etkin kullanıcıda ikinci adım olmadan oturum tamamlanmaz; `security_events` satırları var, parola içermez.

**Kabul ölçütü:** `pnpm verify` OK; `pnpm test:int -- auth-core` PASS; `pnpm --filter @wms/web build` OK; `node scripts/check-docs.mjs` OK.
