# T-105: Staging veritabanı hazırlığı — Neon'da `wms_app` rolü + Fly sırları (iş akışı)
**Faz:** 1 · **Ajan:** devops · **Bağımlılık:** T-005d (Q-06 sonucu), `int/faz1-sema` `main`'de · **Dal:** `feat/T-105-provision-staging` → `int/faz1-staging-db`
**protected: true** (beyan) — `.github/workflows/**`.
**Amaç (tek cümle):** Kullanıcı eylemi gerektirmeden, GitHub Actions'ta `NEON_API_KEY` ile Neon `etkin-wms` projesinin ana dalında `wms_app` rolünü (I-03 nitelikleriyle) kuran/döndüren ve Fly `etkin-wms-staging` uygulamasına `DATABASE_URL` (pooled, `wms_app`) ile uygulama sırlarını yazan, elle tetiklenen iş akışını kurmak.
**Okuma listesi (≤5):** `docs/adr/ADR-013.md`, `docs/adr/ADR-015.md §3–4, §7`, `docs/tasks/T-005d.md` + T-005d özeti (`.artifacts/t-005d/summary.md`, Q-06 satırı), `.github/workflows/deploy-staging.yml` (sır kapsamı ve flyctl kurulum deseni), Neon API "roles / connection_uri" ve `flyctl secrets set --stage` belgesi (Context7/resmî, G-04)
**Dokunulacak dosyalar (≤10):** `.github/workflows/provision-staging.yml`, `scripts/neon-api.mjs`, `scripts/neon-api.test.mjs`, `scripts/provision-staging.mjs`, `scripts/provision-staging.test.mjs`

**Yapılacaklar:**
1. `provision-staging.yml`: yalnızca `workflow_dispatch`, `if: github.ref == 'refs/heads/main'`, `permissions: contents: read`, action'lar tam SHA, flyctl SHA-256 doğrulamalı kurulum (deploy-staging deseni); sırlar (`NEON_API_KEY`, `FLY_API_TOKEN`, `RESEND_API_KEY`) yalnızca ilgili adımın `env`'inde. Değişken `NEON_PROJECT_ID`.
2. `neon-api.mjs` (paylaşılan, yeni bağımlılık yok, `fetch`): ana dal + sahip rolünün **doğrudan** ve **pooled** bağlantı URI'lerini getirir; her değeri önce `::add-mask::` ile maskeler; hiçbir URL/parola/host stdout'a yazılmaz. T-106 aynı modülü kullanır.
3. `provision-staging.mjs`: (a) sahip rolüyle doğrudan bağlantıda `wms_app` yoksa `CREATE ROLE … LOGIN NOSUPERUSER NOBYPASSRLS NOCREATEDB NOCREATEROLE NOREPLICATION` (rastgele 32 bayt parola); varsa `--rotate` girdisiyle parola döndürülür; rol niteliklerini doğrular, sapma → kırmızı. Neon bunu engellerse BLOCKED + Q-06 kaydı. (b) Fly sırları `--stage` ile: `DATABASE_URL` (wms_app, pooled), `BETTER_AUTH_SECRET` ve `DEMO_PASSWORD` (her biri yalnızca yoksa üretilir; A-43), `BETTER_AUTH_URL=https://etkin-wms-staging.fly.dev`, `RESEND_API_KEY` (varsa), `WMS_ENV=staging`. Migration URL'si Fly'a **yazılmaz** (uygulama süreçleri yalnızca `DATABASE_URL` alır — T-005b takibi).
4. Birim testleri: maskeleme (URL/parola içeren girdi çıktıda yok), rol nitelik denetimi, "sır var → yeniden üretme" mantığı (sahte `flyctl`/`fetch`).
5. Ağ notu: ajan ortamından Neon/Fly'a erişim yok; kanıt yalnızca Actions koşusu (GitHub MCP ile özet). İş akışı önce `main`'e birleşir, sonra Supervisor `workflow_dispatch` ile tetikler.

**İnceleme eki (security-reviewer @ 83b5bea):**
- M1/M7: `wms_auth` rolü de aynı niteliklerle kurulur/döndürülür; her iki rol için `pg_auth_members` boş, `NOCREATEROLE`, sahip olunan nesne 0 doğrulanır (sapma → kırmızı). Fly sırrı `AUTH_DATABASE_URL` (`wms_auth`, pooled) yazılır.
- B1 öncülü: Neon sahip rolünün `rolbypassrls`/`rolsuper` değeri özete yazılır (T-103 `SECURITY DEFINER` işlevinin önkoşulu); false ise rapor BLOCKED + ADR-016 §9 yeniden açılır.
- m7: `--rotate-auth-secret` girdisi `BETTER_AUTH_SECRET`'ı yeniler (tüm oturumlar düşer; özet bunu belirtir). `SIGNUP_ENABLED=false` yazılır (A-50).
- m7 (T-106 için): kullanıcıdan istenecek tek hesap işi olarak `STAGING_DATABASE_URL_DIRECT` repo sırrı (migration rolü, yalnızca staging veritabanı) önerisi rapora; sır gelene kadar T-106 `NEON_API_KEY` yolunu kullanır (risk: geniş yetkili API anahtarı dağıtım işinde).

**İnceleme eki 2. tur (security-reviewer @ 0fdea50):**

- 2. tur m1: Fly sır listesine `QUEUE_SEAL_KEY` (32 bayt rastgele, yalnızca yoksa üretilir; döndürme `--rotate-seal-key` ile — yeni `kid`, eski anahtar `QUEUE_SEAL_KEYS_OLD` altında bir süre çözme için).

**İnceleme eki 3. tur (security-reviewer @ b400466):**
- m4 (ADR-015 3. tur eki m4): "sahip rol `ADMIN` olur" yerine `provision-staging.mjs` `GRANT wms_identity_probe TO <sahip/migration rolü> WITH SET TRUE, INHERIT FALSE` kurar ve `pg_auth_members`'ta `set_option=true`, `inherit_option=false` doğrular (sapma → kırmızı). Neon'un bu üyeliğe ve PG16+ sözdizimine izin verdiği, Neon'daki PostgreSQL sürümünde uygulayıcı tarafından doğrulanır (G-04; Q-05/T-005d); izin vermiyorsa BLOCKED + ADR-015 yeniden açılır. Şemada `CREATE` yetkisi migration'dadır (T-103). Özet satırı: `wms_identity_probe: OK (set, noinherit)`. Birim testi: üyelik nitelik denetimi (sahte yanıtla `inherit_option=true` → kırmızı).

**İnceleme eki 5. tur (security-reviewer delta @ 251503f; ADR-015 5. tur eki MINOR-6):** (yeni dosya yok; dosyalar `provision-staging.mjs` + `.test.mjs`)
- PG16+'da `CREATEROLE` sahibi süper kullanıcı olmayan rol (Neon sahip rolü) probe'u oluşturursa kendisine örtük `ADMIN` seçenekli üyelik satırı eklenir (`createrole_self_grant` doluysa ek satır da). Script probe'u oluştururken oturumda `createrole_self_grant` boş olmalıdır; sahip/migration rolü oluşturucuysa `REVOKE ADMIN OPTION FOR wms_identity_probe FROM <migration rolü>` (gerekirse `GRANTED BY` örtük satırın yetki vereni) denenir. Neon izin vermiyorsa: probe'u migration rolü dışındaki bir altyapı rolü oluşturur, migration rolüne yalnızca `WITH ADMIN FALSE, SET TRUE, INHERIT FALSE` verilir; ikisi de olmuyorsa BLOCKED + ADR-015 yeniden açılır. Seçilen yol ve gerekçesi rapora (G-04).
- Doğrulama ADR-015 5. tur eki MINOR-6 kural 1 (tüm satırlar; migration rolünde `admin_option=false`; diğer üyelerde `set`/`inherit` yok, yalnızca-`ADMIN` satırları özete rol adıyla). Özet satırı `wms_identity_probe: OK (set, noinherit, noadmin)`. Birim testi: sahte yanıtla migration rolü satırında `admin_option=true` → kırmızı; başka üyede `set_option=true` → kırmızı.
