# T-009a: Güven kökü kurulumu — ajan kimliği, CODEOWNERS, `main` koruması (kullanıcı eylemi)
**Faz:** 0 · **Ajan:** Supervisor (kullanıcıya adımlar + kanıt toplama) + devops (CODEOWNERS PR'ı) · **Bağımlılık:** T-001b (ADR-012); kod bağımlılığı yok → **hemen başlayabilir**, T-002 ile paralel · **Dal:** `feat/T-009a-trust-root`
**protected: true** (beyan; onay değildir) — `.github/**`.
**Amaç (tek cümle):** ADR-012'deki güven kökünü kurmak: ajan ayrı GitHub kimliğiyle push eder, `main`'e yalnızca PR ile ve korunan yollarda kullanıcının onayıyla girilir, kimse (yönetici dahil) korumayı aşamaz.
**Okuma listesi (≤5):** `docs/adr/ADR-012.md`, `docs/agents/PROTOCOL.md §Onay kaynağı`, `docs/agents/PROTOCOL.md §3b` (korunan yol listesi), `docs/INVARIANTS.md I-17`, GitHub belgesi: CODEOWNERS, rulesets/branch protection, GitHub App izinleri (Context7/resmî; ayar adları bu karttan değil belgeden doğrulanır — G-04)
**Dokunulacak dosyalar (≤10):** `.github/CODEOWNERS`, `docs/adr/ADR-012.md` (yalnızca "Mevcut durum" bölümü; durum "önerildi" kalır)

**Kullanıcı eylemi — ön kararlar (Supervisor tek mesajda sorar):**
- K1 Kimlik türü: **GitHub App** (ADR-012 varsayılanı; kısa ömürlü kurulum token'ı üretmek için ek adım gerekir) / makine kullanıcısı (ayrı hesap + yalnızca bu repoya sınırlı fine-grained token; git'e bağlamak daha basit).
- K2 Ajan ortamı bu kimliği kullanabilir mi? Şu an push'lar oturumun GitHub yetkisiyle gidiyor (ADR-012). Ortam başka kimlik bilgisi kabul etmiyorsa → PROTOCOL "Ayrı kimlik kurulamıyorsa" yolu; **dikkat:** bu durumda PR yazarı kullanıcı olur, GitHub yazarın kendi PR'ını onaylamasına izin vermez → "zorunlu CODEOWNERS onayı + bypass kapalı" birleşemez (kilitlenme). Supervisor bunu seçeneklerle sorar; çözüm uydurulmaz.
- K3 Repo görünürlüğü/planı: branch protection/ruleset bu repoda (private ise mevcut planda) kullanılabiliyor mu? Plan kısıtı olabilir; kullanıcı Settings'te doğrular. Kullanılamıyorsa seçenekler: plan yükseltme / repoyu public yapma / koruma olmadan bilinen risk (Supervisor çoktan seçmeli sorar).

**Kullanıcı eylemi — GitHub adımları (K1–K3 sonrası; ad farkı varsa belgedeki karşılığı):**
1. Kimlik: App ise kullanıcı hesabında oluştur; izinler yalnızca Contents R/W, Pull requests R/W, Workflows R/W (ajan `.github/workflows` yazacak), Metadata R; **Administration yok**; yalnızca bu repoya kur. Makine kullanıcısı ise collaborator rolü **Write** (Admin/Maintain değil). Anahtar/token repoya, loga, karta yazılmaz (G-09); ajan ortamının sır deposuna kullanıcı koyar.
2. CODEOWNERS PR'ını (aşağıda) kullanıcı inceler ve **kendisi** birleştirir.
3. `main` için ruleset (veya klasik koruma): PR zorunlu · en az 1 onay · Code Owners incelemesi zorunlu · yeni commit'te eski onaylar düşer · son push'un onayı zorunlu · force push ve silme yasak · **bypass listesi boş** (klasikte "yöneticiler dahil" seçeneği açık). Zorunlu durum kontrolleri burada seçilmez (iş adları henüz yok) → T-009b.
4. Ajan kimliğinin repo rolünü ve kurulu izinlerini gösteren ekran görüntüsü/API çıktısı Supervisor'a (yalnızca rol/izin; token yok).

**Yapılacaklar (ajan):** `.github/CODEOWNERS`: PROTOCOL §3b korunan yolları + `.github/` + `docs/adr/` + `docs/DECISIONS.md` + `tests/QUARANTINE.md` + `tests/.ac-baseline.json` + `docs/ACCEPTANCE.conditions.json` → `@<kullanıcı-hesabı>` (henüz olmayan yollar desen olarak; takım girdisi yok — T-008c). ADR-012 "Mevcut durum"u K1–K3 sonucu ve kalan riskle güncelle.
**Kabul ölçütü:** Kullanıcının verdiği kanıtla (`.artifacts/T-009a/`): (a) ajan kimliğiyle `main`'e doğrudan push reddedilir (komut çıktısı); (b) CODEOWNERS'lı bir yolu değiştiren PR, GitHub'da "Review required — code owner" gösterir (PR bağlantısı); (c) kullanıcı hesabıyla onaysız birleştirme denemesi engellenir (bypass yok); (d) ajan kimliğinin rolünde Admin yok. K2 "ayrı kimlik yok" ise (a)–(d) yerine ADR-012'de kayıtlı bilinen risk + kullanıcı kararı; kart PARTIAL kapanır.
**Kapsam dışı:** Zorunlu durum kontrolleri ve canlı AC-43 (T-009b), `check:protected` kodu (T-008c).
**Gerekli inceleme:** security-reviewer zorunlu (yetki/izin seti); kullanıcı PR onayı (I-17).
