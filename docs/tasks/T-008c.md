# T-008c: `check:protected` — korunan dosya + insan onayı doğrulaması (AC-43 birim düzeyi)
**Faz:** 0 · **Ajan:** devops · **Bağımlılık:** T-008a (T-008b ile paralel) · **Dal:** `feat/T-008c-check-protected` → `int/faz0-bekciler-1`
**protected: true** (beyan; onay değildir) — bekçi betiği + korunan yol listesi.
**Amaç (tek cümle):** Korunan yol değişikliğinde PR'ın **son commit'ine** CODEOWNERS'taki (hedef daldan okunan) bir insan hesabının onay verdiğini GitHub API'den doğrulayan, doğrulayamazsa kırmızı dönen `pnpm check:protected`'ı yazmak.
**Okuma listesi (≤5):** `docs/agents/PROTOCOL.md §3b` (`check:protected` satırı) + `§Onay kaynağı`, `docs/INVARIANTS.md I-17`, `docs/ACCEPTANCE.md AC-43`, `scripts/guards/lib/git.mjs` + `lib/testkit.mjs`, GitHub REST "pull request reviews" belgesi (Context7/resmî belge; alan adları tahmin edilmez — G-04)
**Dokunulacak dosyalar (≤10):** `scripts/guards/protected.mjs`, `scripts/guards/protected-paths.mjs`, `scripts/guards/lib/github.mjs`, `scripts/guards/lib/codeowners.mjs`, `scripts/guards/protected.test.mjs`, `scripts/guards/lib/codeowners.test.mjs`, `tests/guards/ac-43.test.mjs`

**Yapılacaklar:**
1. `protected-paths.mjs` (tek kaynak): PROTOCOL §3b listesi — `docs/INVARIANTS.md`, `docs/ACCEPTANCE.md`, `docs/spec/16-stock-effects.md`, `packages/db/src/locking.mjs`, `main`'de var olan migration dosyaları (değişiklik/silme; yeni migration korunmaz), `.github/**`, lint/tsconfig/test yapılandırmaları (`eslint.config.mjs`, `**/tsconfig*.json`, `vitest.config.*`, `playwright.config.*`), `scripts/verify.mjs`, `scripts/check-docs.mjs` (T-004), `scripts/guards/**`, `scripts/test-ac/**`, `scripts/lib/**`, `.githooks/**`, kök `package.json`'da ORM/sürücü/pooler sürüm alanları ve compose'daki pooler imaj etiketi. §Onay kaynağı listesinden türeyenler: `tests/.ac-baseline.json` (yalnızca **düşüş**; artış serbest), `tests/QUARANTINE.md`, `docs/ACCEPTANCE.conditions.json`, `docs/DECISIONS.md` ve `docs/adr/ADR-*.md`'de durumun "kabul"e geçmesi. Gerçek yollar repoda grep'lenir; yoksa desen olarak kalır (G-05).
2. `lib/github.mjs`: `fetch` ile (yeni bağımlılık yok) PR head SHA, incelemeler, birleştiren hesap; `GITHUB_TOKEN`/`GITHUB_REPOSITORY`/PR no ortamdan. Arayüz enjekte edilebilir (test çifti yalnızca testte; üretimde sahte istemci yok — G-07).
3. Kural: korunan değişiklik varsa en az bir inceleme `state=APPROVED` ∧ `commit_id == head SHA` ∧ incelemeci hesap türü `User` ∧ incelemeci, **hedef daldaki** CODEOWNERS'ta o yolun sahibi. Karttaki `protected: true` hiçbir koşulu karşılamaz. Makine kullanıcısının türü de `User` olduğundan asıl kontrol CODEOWNERS üyeliğidir; CODEOWNERS'ta takım (`@org/team`) girdisi → FAIL `CODEOWNERS_TEAM_UNSUPPORTED` (üyelik çözümlemesi bu kartta yok, fail-closed). `main`'de CODEOWNERS yoksa → `APPROVAL_UNVERIFIABLE`.
4. Fail-closed: API erişimi/izin yoksa, PR bağlamı yoksa CI'da → FAIL `APPROVAL_UNVERIFIABLE`. Yerel kanca modu (`--local`) yalnızca uyarır `PROTECTED_CHANGE_NEEDS_APPROVAL` (çıkış 0) — onay yerelde doğrulanamaz; zorlama CI'dadır.
5. Neden kodları: `PROTECTED_NO_APPROVAL`, `APPROVAL_STALE`, `APPROVER_NOT_CODEOWNER`, `APPROVER_NOT_HUMAN`, `APPROVAL_UNVERIFIABLE`; dosya yolu ile.
6. Korunan dosya ilk oluşturma akışı T-007 Yapılacaklar 6 ile aynı.

**Kabul ölçütü:** `pnpm vitest run scripts/guards/protected.test.ts scripts/guards/lib/codeowners.test.ts tests/guards` yeşil. `tests/guards/ac-43.test.mjs` başlıkları `@AC-43` taşır ve AC-43'ün dört durumunu (beyan, ajan/bot onayı, eski commit'e onay, PR dalında değişmiş CODEOWNERS) ayrı ayrı FAIL + doğru neden kodu, son commit'e CODEOWNER insan onayını OK olarak doğrular; ayrıca API yok → FAIL, baseline artışı → korunan sayılmaz, düşüşü → korunan. `pnpm test:ac -- AC-43` PASS. Canlı GitHub kanıtı T-009b'de. `pnpm verify` özeti raporda.
