# T-222: Eşik üstü belge işleme — worker'da tek transaction, aynı idempotency anahtarı, istek sahibi aktör, işleme kilidi (AC-36)
**Faz:** 2 · **Ajan:** backend-dev · **Bağımlılık:** T-221 (`posting.ts` sıcak dosya), T-214 (`stock.document.post` iş türü, `consumeOnce`) · **Dal:** `feat/T-222-async-posting` → `int/faz2-async` (taban: `int/faz2-rezervasyon` T-221 sonrası + `int/faz2-kuyruk` birleştirmesi)
**Amaç (tek cümle):** Satır sayısı senkron eşiğin (200, A-07) üstündeki belgeyi istek transaction'ında `APPROVED` + `posting_job_id` + `posting_requested_by` + `IN_PROGRESS` idempotency kaydıyla kuyruğa bırakıp worker'da istek sahibinin güncel yetkisiyle aynı 7 adımla tek transaction'da `POSTED` yapmak; işleme sürerken belgeyi diğer komutlara kapatmak; sert sınır (2.000) üstünü reddetmek.
**Okuma listesi (≤5):** `docs/spec/05-stock-engine.md §Senkron işlem sınırları`, `docs/adr/ADR-018.md §3, §6`, `docs/adr/ADR-019.md §1–§3`, `packages/domain/src/stock/posting.ts` (T-217/T-221), `apps/worker/src/main.ts` (iş kaydı, `DEFERRED_JOB_TYPES`; `grep -n "work\|handler\|DEFERRED"`)
**Dokunulacak dosyalar (≤10):** `packages/domain/src/stock/posting.ts`, `packages/domain/src/stock/jobs.ts`, `packages/domain/package.json`, `apps/worker/src/jobs/post-stock-document.ts`, `apps/worker/src/jobs/post-stock-document.test.ts`, `apps/worker/src/main.ts`, `tests/integration/stock/async-posting.int.test.ts`

**Yapılacaklar:**
1. `posting.ts`: satır sayısı > 200 → `requestAsyncPosting` (tek transaction): belge `FOR UPDATE` + sürüm; `posting_job_id` doluysa `DOCUMENT_STATE`; belge `APPROVED` kalır, `posting_job_id` + `posting_requested_by = çağıran` yazılır, idempotency `IN_PROGRESS`, `enqueue(tx, { type: "stock.document.post", actorUserId: çağıran, payload: { documentId, idempotencyRecordId }, singletonKey: documentId })` (tenant `tx`'ten, ADR-016 §12); yanıt `{ status: "PROCESSING", documentId }`. T-217'deki geçici "async gerekli" reddi kaldırılır. Aynı anahtarla tekrar → `IN_PROGRESS` sonucu; yeni anahtarla tekrar → `DOCUMENT_STATE` (M-6).
2. `jobs.ts` (`exports["./stock/jobs"]`): `runAsyncPosting(ctx)` — aktör = `ctx.actorUserId` (istek sahibi, M-5; `posting_requested_by` ile eşleşmezse iş kalıcı hata, log); `withMembership({ userId: actor, permission: stock.post })` güncel yetkiyle (ADR-016 §6); kilitli belgede `status = 'APPROVED' ∧ posting_job_id = ctx.jobId` değilse etkisiz biter (iptal/yarış; yalnız log + `processed_events`); `consumeOnce(tx, "stock.document.post", ctx.jobId, …)` içinde aynı `executeStockCommand` yolu; başarıda idempotency `COMPLETED`, `posting_job_id = NULL`, audit aktörü istek sahibi.
3. Kalıcı hata (iş kuralı reddi, yetki kaybı; MINOR-7): ana transaction geri alınır; **ayrı transaction**'da idempotency `FAILED` + `error_code`, belge `posting_job_id = NULL` (`APPROVED` kalır), durum geçmişi + audit ve `processed_events` birlikte; pg-boss işi kalıcı başarısız (`isPermanentFailure`). Geçici hata → pg-boss yeniden dener, ayrı yazım yok.
4. `getPostingStatus(documentId)` (`stock.view`): `DRAFT|APPROVED|PROCESSING|POSTED|FAILED(kod)`; UI (T-229) yoklar.
5. Worker: `post-stock-document.ts` handler; `main.ts` kaydı ve türün `DEFERRED_JOB_TYPES`'tan çıkarılması; worker `statement_timeout`/`lock_timeout` (A-75).
6. Sert sınır: > 2.000 satır `DOCUMENT_TOO_LARGE` (T-213); işleme anında yeniden denetlenir.
7. Ölçüm (MINOR-12): 2.000 satırlık belgenin worker transaction süresi ve aynı boyutlara eşzamanlı 20 senkron komutun `VERSION_CONFLICT` oranı → rapora (eşik değil; A-75/A-07 girdisi).
8. Testler: handler birimi (kalıcı/geçici sınıflandırma, aktör uyuşmazlığı); entegrasyon: 250 satırlık belge → `PROCESSING`, worker koşunca tek transaction'da `POSTED` (defter `created_xid` tek değer), tekrar istek yeni iş üretmez; `stock.post` izni olmayan kullanıcı belgeyi oluşturmuş, yetkili kullanıcı işleme istemiş → `POSTED` ve audit aktörü işleme isteyen; işlemedeyken `cancelDocument`/`reserve`/yeni anahtarla `postDocument` → `DOCUMENT_STATE`; işleme isteyenin üyeliği kalkınca → `FAILED` (`FORBIDDEN`), stok etkisi yok; handler ortasında süreç öldürülür → yeniden teslimde tek etki.

**Kabul ölçütü:** `pnpm verify` OK; `pnpm test:int -- async-posting` PASS + tam koşu PASS; madde 7 ölçümü rapora. AC-36 kabul testi T-228 (worker) ve T-230 (UI).
