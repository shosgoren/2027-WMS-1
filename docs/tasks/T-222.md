# T-222: Eşik üstü belge işleme — worker'da tek transaction, aynı idempotency anahtarı, "işleniyor" durumu (AC-36)
**Faz:** 2 · **Ajan:** backend-dev · **Bağımlılık:** T-221 (`posting.ts` sıcak dosya), T-214 (`stock.document.post` iş türü, `consumeOnce`) · **Dal:** `feat/T-222-async-posting` → `int/faz2-async` (taban: `int/faz2-rezervasyon` T-221 sonrası + `int/faz2-kuyruk` birleştirmesi)
**Amaç (tek cümle):** Satır sayısı senkron eşiğin (200, A-07) üstündeki belgeyi istek transaction'ında `APPROVED` + `posting_job_id` + `IN_PROGRESS` idempotency kaydıyla kuyruğa bırakıp worker'da aynı 7 adımla tek transaction'da `POSTED` yapmak; sert sınır (2.000) üstünü reddetmek.
**Okuma listesi (≤5):** `docs/spec/05-stock-engine.md §Senkron işlem sınırları`, `docs/adr/ADR-018.md §6`, `docs/adr/ADR-019.md §2, §5, §6`, `packages/domain/src/stock/posting.ts` (T-217/T-221), `apps/worker/src/main.ts` (iş kaydı; `grep -n "work\|handler"`)
**Dokunulacak dosyalar (≤10):** `packages/domain/src/stock/posting.ts`, `packages/domain/src/stock/jobs.ts`, `packages/domain/package.json`, `apps/worker/src/jobs/post-stock-document.ts`, `apps/worker/src/jobs/post-stock-document.test.ts`, `apps/worker/src/main.ts`, `tests/integration/stock/async-posting.int.test.ts`

**Yapılacaklar:**
1. `posting.ts`: satır sayısı > 200 → senkron işleme yerine `requestAsyncPosting`: tek transaction'da belge `APPROVED` kalır, `posting_job_id` yazılır, idempotency `IN_PROGRESS`, `enqueue(tx, { type: "stock.document.post", payload: { documentId, idempotencyRecordId }, singletonKey: documentId })` (ADR-016 §12: tenant `tx`'ten); yanıt `{ status: "PROCESSING", documentId }`. T-217'deki geçici "async gerekli" reddi kaldırılır. Aynı anahtarla tekrar → `IN_PROGRESS` sonucu (yeni iş yok).
2. `jobs.ts` (`exports["./stock/jobs"]`): `runAsyncPosting(ctx)` — `ctx.inTenant` değil, ADR-016 §6 gereği belgeyi oluşturan kullanıcı adına `withMembership(stock.post)` (güncel yetki; üyelik kalktıysa belge gerekçeli `FAILED`); `consumeOnce(tx, "stock.document.post", ctx.jobId, …)` içinde aynı `executeStockCommand` yolu; belge zaten `POSTED` ve idempotency `COMPLETED` → etkisiz biter.
3. Kalıcı hata (iş kuralı reddi, ör. `INSUFFICIENT_STOCK`): aynı transaction'da idempotency `FAILED` + hata kodu, belge `APPROVED` kalır, `posting_job_id` temizlenir, audit; pg-boss işi kalıcı başarısız işaretlenir (`isPermanentFailure`), yeniden denenmez. Geçici hata (bağlantı, `VERSION_CONFLICT` tükenmesi) → pg-boss yeniden dener.
4. `getPostingStatus(documentId)` okuyucusu (`stock.view`): `DRAFT|APPROVED|PROCESSING|POSTED|FAILED(kod)`; UI (T-229) yoklar.
5. Worker: `post-stock-document.ts` handler + `main.ts` kaydı; `statement_timeout` worker değeri (A-75).
6. Sert sınır: > 2.000 satır belge oluşturma/güncelleme zaten `DOCUMENT_TOO_LARGE` (T-213); işleme anında yeniden denetlenir.
7. Testler: handler birimi (kalıcı/geçici hata sınıflandırması); entegrasyon: 250 satırlık belge → `PROCESSING`, worker koşunca tek transaction'da `POSTED`, defter satır sayısı = 250 (×2 MOVE için), tekrar istek yeni iş üretmez; handler ortasında süreç öldürülür → yeniden teslimde tek etki.

**Kabul ölçütü:** `pnpm verify` OK; `pnpm test:int -- async-posting` PASS + tam koşu PASS. AC-36 kabul testi T-228 (worker) ve T-230 (UI).
**Kapsam dışı:** Ekran (T-229), tutarlılık işi (T-225), import'un belgeyi bölmesi (4P).
**Risk:** A-07 eşikleri ölçümle (AC-36 koşusu) değişebilir; tek transaction'daki 2.000 satırın kilit süresi ölçülüp rapora yazılır (p95 > 1 sn alarm eşiği yalnızca senkron yol için).
**Gerekli inceleme:** security-reviewer zorunlu (kuyruk tüketicisi, stok motoru, worker yetkisi); bağımsız qa T-228. Paket `int/faz2-async` (paketin ilk kartı; migration yok).
