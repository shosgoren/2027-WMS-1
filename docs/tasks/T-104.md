# T-104: Bağımsız doğrulama — şema/RLS izolasyonu (AC-04 DB katmanı) + `withMembership` (AC-18 DB katmanı)
**Faz:** 1 · **Ajan:** qa-verifier · **Bağımlılık:** T-101, T-101b, T-102, T-103 (aynı int dalında) · **Dal:** `feat/T-104-qa-schema` → `int/faz1-sema`
**Amaç (tek cümle):** Uygulayıcıdan bağımsız olarak, Faz 1 şemasındaki her tenant tablosunun iki tenantlı RLS izolasyonunu ve çıkarılmış üyeliğin/askıdaki tenant'ın DB katmanında yazamadığını `@AC-04` ve `@AC-18` etiketli testlerle kanıtlamak.
**Okuma listesi (≤5):** `docs/ACCEPTANCE.md AC-04, AC-18`, `docs/adr/ADR-016.md §2–5`, `docs/INVARIANTS.md I-01…I-03`, `packages/db/src/with-membership.ts`, `tests/integration/ac/ac-05-pooler-isolation.int.test.ts` (desen)
**Dokunulacak dosyalar (≤10):** `tests/integration/ac/ac-04-db-isolation.int.test.ts`, `tests/integration/ac/ac-18-membership-db.int.test.ts`, `tests/integration/fixtures/tenants.ts`, `tests/.ac-baseline.json`

**Yapılacaklar:**
1. `fixtures/tenants.ts`: migration rolüyle iki tenant (A, B), her birinde kullanıcı + üyelik + rol + davet + ayar; tohum sentetik (G-09).
2. AC-04 (DB): `wms_app` + PgBouncer üzerinden, A bağlamında her tenant tablosu için B'nin `id`'siyle SELECT → 0 satır; UPDATE/DELETE → 0 satır etkilenir; B `tenant_id`'siyle INSERT → RLS hatası; bağlamsız (`withTenant` dışı) sorgu → 0 satır / ret. Tablolar `information_schema`'dan **dinamik** listelenir (tenant_id sütunu olan her tablo); yeni tablo eklenince test kendiliğinden kapsar, listede olup RLS'i `FORCE` olmayan tablo → FAIL.
3. AC-04 (DB): `withUser` ile kullanıcı yalnızca kendi üyeliklerini ve o tenant'ların `tenants` satırını görür; başka hiçbir tenant tablosu satırı gelmez.
4. AC-18 (DB): üyelik `REMOVED` yapıldıktan sonra (migration rolüyle, ayrı transaction) aynı kullanıcı için `withMembership` + yazma → `FORBIDDEN`, yazma kalıcı değil; tenant `SUSPENDED` → `TENANT_SUSPENDED`; eşzamanlılık: çıkarma commit'i yazma transaction'ından önce → yazma reddedilir (T-103 yarış testinden bağımsız yeniden yazılır).
5. Test başlıkları `@AC-04` / `@AC-18` içerir; dosya başında "katman: DB — API/dosya/cache/export katmanları T-128, oturum katmanı T-120" notu.
6. `pnpm check:ac-ratchet --update` ile tabana ekle (yalnızca artış).

**İnceleme eki (security-reviewer @ 83b5bea):**
- M7: rol nitelik testleri paket dosya sınırı nedeniyle T-108'e taşındı (`roles.int.test.ts`); bu pakette `0001`/`0002` migration'larının `RAISE` denetimleri ilk savunmadır.
- M8: `wms_app` ile A bağlamında `UPDATE tenants SET status='ACTIVE'` / `is_demo` / `slug` → yetki hatası; `name` güncellemesi yalnızca kendi tenant'ında.
- m1: A tenant bağlamı kurulu ve `app.current_user_id` elle B üyesinin kimliğine set edilmişken B'nin üyelik/tenant satırları görünmez (kullanıcı politikası tenant bağlamında devre dışı).
- ADR-016 risk: `pg_proc` taramasında `prosecdef=true` uygulama işlevleri yalnızca izinli liste (`identity_exclusive_to_tenant`).

**İnceleme eki 2. tur (security-reviewer @ 0fdea50):**

- 2. tur m4: `wms_app` ile `is_demo`/`status` sütunlu `tenants` INSERT → yetki hatası.

**İnceleme eki 3. tur (security-reviewer @ b400466):**

**İnceleme eki 4. tur (security-reviewer delta @ c9195ef):**

- MINOR-6: `tenant_memberships`/`membership_roles` demo bekçi tetikleyici işlevi `prosecdef = false` (izinli listeye girmez; `SECURITY DEFINER` olursa FAIL).

**İnceleme eki 5. tur (security-reviewer delta @ 251503f):**
