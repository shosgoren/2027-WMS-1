**Yapılacaklar:**
1. `reverseDocument({ documentId, lines: [{ lineId, quantity }] | "ALL", reason, clientKey })` (`reversal.create`): `executeStockCommand`; plan `document` = asıl belge + sürüm (kilitli), boyutlar = asıl satırların boyutları, yeni `REVERSAL` belgesi INSERT (kilit gerekmez; ADR-018 §7).
2. Sınırlar: satır başına `quantity ≤ base_quantity − reversed_quantity` (aksi `REVERSAL_BLOCKED`, ayrıntıda kalan miktar); ters yön bakiyeyi negatife düşürecekse (sonraki çıkış/taşıma tüketmiş) `REVERSAL_BLOCKED` + "kalan X; en çok X ters çevrilebilir" bilgisi (Senaryo C satır 1); hedef boyutta aktif rezervasyon ters çevrilecek miktarı kullanılabilirden düşürüyorsa `REVERSAL_BLOCKED` (rezervasyon önce serbest bırakılmalı); seri hareketi sonrası başka belgeyle taşınmış seri → `REVERSAL_BLOCKED`. Kapalı dönem denetimi yok (A-71).
3. Yazım: ters işaretli defter satırları (`reason = REVERSAL`), bakiye, asıl satırlarda `reversed_quantity` artışı ve `reversal_status` `PARTIAL|FULL` (DB tetikleyicisi yalnızca artışa izin verir), `REVERSAL` belgesi `POSTED` + `reversal_of_document_id`, audit `stock_document.reversed` (gerekçe, aktör, kaynak ve ters belge bağlantısı — 05 §Geri alma).
4. Ters kaydın ters kaydı reddedilir (`DOCUMENT_STATE`); `CANCELLED`/`DRAFT` belge → `DOCUMENT_STATE`.
5. Aynı istek tekrarı (aynı anahtar) → ilk sonuç, ikinci etki yok (Senaryo C satır 3).
6. Testler: birim (kalan hesap, satır seçimi doğrulaması); entegrasyon: Senaryo C üç satırı birebir (100 giriş, 60 çıkış → tam ters `REVERSAL_BLOCKED`, hiçbir satır yazılmaz; 40 ters → `R-01·KUL = 0`, `PARTIAL` 40/100; tekrar → ilk sonuç); `STOCK_MOVE` ters kaydı iki boyutu birlikte geri alır.
