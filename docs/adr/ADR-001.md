# ADR-001: Uygulama mimarisi — Next.js App Router monolit + ayrı kalıcı worker

**Tarih / Durum:** 2026-10-05 · **kabul** (ADR-012 rev., kullanıcı kararı 2026-10-05)

**Bağlam:**
- v1.3 şartnamesi NestJS API + Next.js ön yüz + RabbitMQ + Azure Blob öneriyordu; güncel şartname (`docs/spec/01-scope-stack.md §Mimari`) modüler monolit önerir.
- Stok ve yetki kuralları web isteği ile arka plan işleri (import, export, OCR, bildirim, outbox relay, silme, tutarlılık kontrolü) arasında birebir aynı olmalı; kopyalanan kural sapma riskidir.
- Worker işleri uzun sürer; serverless fonksiyon süre/bağlantı sınırlarına bağlanmamalıdır.
- Kullanıcı kararı 2026-10-05 (sohbet; seçenekler önerili sunuldu, `docs/tasks/T-001.md`).

**Seçenekler:**
| Seçenek | Artı | Eksi |
|---|---|---|
| **A. Next.js App Router monolit + ayrı kalıcı worker, pnpm monorepo, ortak `packages/domain`** (seçilen) | Tek dil/tek repo; web ve worker aynı domain komutlarını import eder; ayrı API katmanı ve aradaki sözleşme/serileştirme yükü yok; ajanlar için daha az hareketli parça | Route Handler/Server Action'ların ince kalması disiplin ister (domain mantığı UI katmanına sızabilir); dış entegrasyonlar için ayrı public API ileride ayrıca tasarlanmalı |
| B. NestJS API + Next.js ön yüz (v1.3) | Olgun modül/DI yapısı; API sınırı doğal olarak ayrık | İki uygulama, iki çalışma zamanı yapılandırması; ön yüz ↔ API sözleşmesi ve kimlik doğrulama iki kez; worker ile kural paylaşımı yine ortak paket gerektirir |

**Karar:** Seçenek A.
- Yapı: `apps/web` (Next.js App Router), `apps/worker` (uzun ömürlü, istek süreçlerinden ayrı, serverless olmayan süreç), `packages/domain`, `packages/db`, `packages/shared`, `packages/ui`.
- Route Handlers ve Server Actions yalnızca ince giriş katmanıdır; domain servislerini çağırır. Stok değişimi yalnızca `packages/domain` stok komutlarıyla olur (G-01).
- **v1.3'ten sapma (açık kayıt):**
  - *NestJS API → reddedildi* (bu ADR). Gerekçe: web ve worker'ın aynı domain komutlarını tek süreç modeliyle paylaşması, ayrı API katmanının getirdiği ikinci sözleşme/kimlik doğrulama yüzeyinin kaldırılması.
  - *RabbitMQ* bu ADR'de **seçilmez ve reddedilmez**; kuyruk kararı ADR-005'tedir (T-001b). Domain yalnızca `JobQueue` arayüzünü görür (`docs/STACK.md §ADR-005`), sağlayıcı değişimi domain'i etkilemez.
  - *Azure Blob* bu ADR'de **seçilmez ve reddedilmez**; dosya deposu kararı ADR-006'dadır (T-001b). Erişim `ObjectStorage` arayüzü arkasındadır.

**Sonuçlar ve riskler:**
- Web ve worker aynı `packages/domain`/`packages/db` sürümünü kullanır; tenant bağlamı her ikisinde de `withTenant` ile kurulur (G-02).
- Risk: domain mantığının Server Action/Route Handler içine yazılması → kural sapması. Önlem: inceleme + ileride import sınırı lint kuralı (ayrı kart; bu ADR mevcut bir bekçi iddia etmez).
- Risk: worker'ın kalıcı süreç olması barındırma ortamının uzun ömürlü süreç desteklemesini gerektirir; barındırma platformu bu ADR'de seçilmez (bölge: ADR-007).
- Kuyruk (ADR-005) ve dosya (ADR-006) kararları bu yapıyı değiştirmez; yalnızca `packages/queue-adapter` ve depolama adaptörünü etkiler.
- Sürümler (Node.js, Next.js, pnpm) bu ADR'de kilitlenmez → `docs/STACK.md` sürüm kilidi (T-004).

**Doğrulama:**
- Faz 0 iskelet kartında `apps/web`, `apps/worker` ve `packages/*` oluşur; `pnpm verify` yeşil; worker web'den bağımsız başlatılır.
- Aynı domain komutu web ve worker'dan çağrıldığında aynı sonucu verir (Faz 2 stok çekirdeği testleri).
