# ADR-012: Ajan GitHub kimliği ve onay kaynağı

**Tarih / Durum:** 2026-10-05 · **kabul** (2026-10-05 revizyonu; kullanıcı kararı aşağıda)

**Bağlam:**
- İlk sürüm (önerildi): ajanlar ayrı GitHub kimliğiyle push eder; korunan yollar ve ADR kabulü için onay yalnızca kullanıcının GitHub incelemesinden gelir (I-17); T-009'a kadar `main`'e yalnızca kullanıcı birleştirir.
- Ayrı ajan kimliği yok (T-009a K2, kullanıcı 2026-10-05). Push'lar oturumun GitHub yetkisiyle (kullanıcının hesabı) gidiyor.
- Kullanıcı sürekli başında değil; PR incelemesi ilerlemeyi durduruyordu.

**Seçenekler:**
| Seçenek | Artı | Eksi |
|---|---|---|
| A. GitHub App + kullanıcı incelemesi (ilk öneri) | Onay ajandan bağımsız | Kullanıcının her korunan PR'ı incelemesi gerekir; ilerleme durur |
| B. Kullanıcı yalnızca faz kapısında toplu inceler | Daha az kesinti | Yine kullanıcı zamanına bağlı |
| **C. Mekanik kapılar + bağımsız ajan incelemesi, Supervisor birleştirir** (seçilen) | Kesintisiz ilerleme; kontroller makinede | Onay ajandan bağımsız değil (bilinen risk) |

**Karar (kullanıcı, 2026-10-05, sohbet talimatı — birebir özet):** "Hiçbir PR'ı ben incelemeyeceğim. Kontrolü sen yap: otomatik testler, bekçiler, security-reviewer ve qa-verifier ajanları geçtiğinde kendi PR'ını kendin birleştir; ADR'ler bu kararla kabul sayılır."
1. **Onay kaynağı = birleştirme kapısı.** Supervisor bir PR'ı `main`'e (veya `int/*` dalını üst dala) şu koşulların **hepsi** sağlanınca kendisi birleştirir:
   - CI'daki tüm zorunlu işler yeşil (T-003 sonrası: `pnpm verify`, `pnpm check:all`, `pnpm test:int`, ilgili `pnpm test:ac`); CI kurulmadan önce aynı komutlar oturumda koşturulur ve özet satırları PR açıklamasına yazılır. Kod içermeyen (yalnızca `docs/`) PR'larda komut yoksa "çalıştırılmadı — kod yok" yazılır.
   - Risk matrisinin (PROTOCOL §2.5) istediği `security-reviewer` ve bağımsız `qa-verifier` raporları **BLOCKER: 0** ile PR açıklamasında (rapor özeti + karar).
   - Korunan dosya değişikliği, `tests/.ac-baseline.json` düşürülmesi, karantina, AC faz değişikliği: ayrı ve küçük PR, gerekçe PR açıklamasında, `security-reviewer` incelemesi zorunlu; `check:protected` bu PR'larda insan onayı yerine **`APPROVED-BY: supervisor (ADR-012 rev.) @ <PR head SHA>` satırı + `security-reviewer: BLOCKER: n · MAJOR: n · MINOR: n` özet satırı** arar (rapor bağlantısı önerilir, zorunlu değil). Bekçi gevşetme (eşik düşürme, kural kapatma) ise yine yasaktır (G-11); bunu gerektiren durum BLOCKED raporlanır.
2. **ADR'ler:** ADR-001…012 bu kararla **kabul**. Koşullu olanlar koşullarını korur: ADR-004 teknik alanları T-005 sonucuyla doldurulur; ADR-007 kabul edildi ama **hukukçu onayı (Q-07) gelmeden gerçek kişisel veri prod'a yazılmaz** — canlı ortam yalnızca demo/sentetik veriyle çalışır. Yeni ADR'ler `architect` tarafından yazılır, `security-reviewer` güvenlik etkisi varsa inceler, Supervisor kabul eder.
3. **Faz kapıları:** Kapı AC'leri `pnpm test:ac --phase N` ile geçince Supervisor sonraki faza geçer; kapı raporu `JOURNAL.md`'ye ve STATE'e yazılır, kullanıcıya ayrıca gönderilmez.
4. **Kullanıcıya yazılan tek durum:** kullanıcının kendi hesabını/ödemesini/hukuki imzasını gerektiren işler (ör. Neon, barındırma, e-posta sağlayıcısı hesabı, hukukçu onayı). Bunlar tek mesajda toplanır. Proje canlıya çıkınca canlı adres + deneme rehberi gönderilir.
5. **Değişmeyenler:** veri kaybettiren migration'ın gerçek kullanıcı verisi olan ortamda çalıştırılması, ödeme sağlayıcısında canlı ayar ve repoyu/dalları silme hâlâ kullanıcı onayı ister. `main`'e force push yok. Sırlar repoya/loga/rapora girmez (G-09).
6. **Ayrı kimlik ve CODEOWNERS:** kurulmaz (T-009a'nın kimlik/CODEOWNERS kısmı iptal). `main` için branch protection (PR zorunlu, zorunlu durum kontrolleri, force push kapalı) kullanıcının GitHub ayarıyla açılırsa mekanik kapıyı güçlendirir; açılmazsa Supervisor CI durumunu GitHub API'den okuyup kırmızıyken birleştirmez.

**Sonuçlar ve riskler:**
- **Bilinen risk (her faz kaydında tekrarlanır):** onay, değişikliği yapan sistemden bağımsız değil. Ajan kendi PR'ını birleştirir; `check:protected` insan onayını kimlikten ayırt edemez. Azaltma: mekanik bekçiler (G-11 — bekçi gevşetme yasak), bağımsız bağlamda koşan `security-reviewer`/`qa-verifier`, küçük PR, her birleştirmenin PR açıklamasında kanıt.
- Kullanıcı bu kararı istediği an geri alabilir; o durumda bu ADR'nin yerine geçen kayıt yazılır ve ilk sürümdeki (Seçenek A) akış döner.

**Doğrulama:** Her birleştirilen PR'ın açıklamasında: CI bağlantısı/özet satırları, gerekli inceleme raporlarının BLOCKER sayısı, `APPROVED-BY` satırı (korunan değişiklikte). T-008c `check:protected` bu satırı denetler.
