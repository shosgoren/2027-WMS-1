# ADR-005: İş kuyruğu — Postgres kuyruğu, `JobQueue` arayüzü arkasında

**Tarih / Durum:** 2026-10-05 · **kabul** (ADR-012 rev., kullanıcı kararı 2026-10-05)

**Bağlam:**
- v1.3 RabbitMQ öneriyordu; ADR-001 kuyruğu bu ADR'ye bıraktı. Seçenek analizi `docs/STACK.md §ADR-005`.
- Yan etki işleri (bildirim, export, entegrasyon, rapor, eşik üstü belge kesinleştirme) stok işlemiyle tutarlı kuyruğa girmelidir; ayrı broker outbox relay hop'u gerektirir.
- Varsayılan kullanıcıya 2026-10-05'te sunuldu, itiraz gelmedi (`docs/tasks/T-001b.md`); bu onay sayılmaz.

**Seçenekler:**
| Seçenek | Artı | Eksi |
|---|---|---|
| **A. Postgres kuyruğu (pg-boss veya graphile-worker)** (seçilen, Faz 0–4) | İş, stok işlemiyle aynı transaction'da yazılır (outbox = kuyruk); Redis yok | Yük DB'ye biner; yüksek hacimde geçiş gerekir |
| B. BullMQ + Redis | Yüksek hacim, hız sınırı, tenant adaleti | Outbox relay + Redis işletimi |
| C. RabbitMQ (v1.3) | Olgun yönlendirme | Ek altyapı + relay hop'u |

**Karar:** Seçenek A.
- Kütüphane (pg-boss / graphile-worker) bu ADR'de seçilmez; T-002'de lisans ve bakım durumu doğrulanarak seçilir ve bu ADR'ye ek olarak yazılır.
- **Ek (2026-10-05, Supervisor; girdi T-002c bulgusu):** **pg-boss** (12.36.0, MIT, son yayın 2026-10-02) seçildi. Gerekçe: kilitler transaction kapsamlı (`pg_advisory_xact_lock`) → transaction-mode pooler ile uyumlu; varsayılan polling (LISTEN/NOTIFY isteğe bağlı, ayrı bağlantı); iş, uygulama transaction'ı içinde oluşturulabilir (outbox ile aynı transaction). graphile-worker 0.18.0 LISTEN/NOTIFY'ı kapatamıyor ve session bağlantısı istiyor. API ayrıntıları ilk kuyruk kartında kurulu tiplerden doğrulanır (G-04); doğrulama başarısızsa bu ek yeniden açılır.
- Domain yalnızca `packages/shared` içindeki `JobQueue` arayüzünü görür; sağlayıcı kütüphanesi yalnızca `packages/queue-adapter` içinde import edilir (`STACK.md §ADR-005`).
- İş birimi belge/olaydır, satır değildir; tamamlanan işler arşive taşınır/silinir.
- **BullMQ'ya geçiş ölçütleri:** kuyruk tablosu dead tuple sayısı, kuyruk kaynaklı WAL hacmi (MB/saat), iş gecikmesi p95 (sn), saniyedeki iş sayısı. Sayısal eşik değerleri ilk yük profili ölçümünden sonra yazılır → `Q-11`.
- RabbitMQ reddedildi (v1.3'ten sapma): ek altyapı ve relay hop'u, Faz 0–4 hacminde gerekçesiz.

**Sonuçlar ve riskler:**
- Redis `docker compose`'a eklenmez (CLAUDE.md: redis yalnızca broker seçilirse).
- Risk: kuyruk tablosu şişkinliği → agresif autovacuum + arşivleme; ölçümler izlenir.
- Risk: eşik değerleri belirlenene kadar geçiş kararı ölçüme dayanamaz (`Q-11`).

**Doğrulama:** Adapter sözleşme testleri (AC-16, AC-22, AC-23); `enqueue(tx, job)` geri alınan transaction'da işin yazılmadığını gösteren entegrasyon testi; geçiş ölçütlerinin metrik olarak toplanması.
