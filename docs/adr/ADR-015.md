# ADR-015: Migration aracı, rol ayrımı ve dağıtım sırası

**Tarih / Durum:** 2026-10-05 · **önerildi** (architect, Faz 1 planı; ADR-012 rev.: Supervisor kabul eder; RLS/rol etkisi nedeniyle `security-reviewer` zorunlu)

**Bağlam:**
- G-08: migration'lar genişlet–taşı–daralt; veri kaybettirmeyenlerde **down migration zorunlu**. `14 §CI`: migration ileri/geri CI'da. Birleşmiş migration korunan dosyadır (`MIGRATION_GLOBS` = `**/migrations/**`, `**/drizzle/**`).
- I-03: uygulama rolü (`wms_app`) tablo sahibi/süper kullanıcı/BYPASSRLS değildir; migration rolü ayrıdır. Yerel/CI'da `wms_migrator` (compose bootstrap kullanıcısı) + `wms_app` (`infra/postgres/init/01-roles.sh`). Neon karşılığı Q-06 / T-005d.
- Drizzle 0.45.3 kurulu; `drizzle-kit` kurulu değil. `drizzle-kit` yalnızca ileri (up) SQL üretir; down üretmez.

**Seçenekler:**
| Seçenek | Artı | Eksi |
|---|---|---|
| **A. Elle yazılmış SQL çiftleri (`NNNN_ad.up.sql` / `.down.sql`) + `packages/db` içinde küçük koşturucu; Drizzle TS şeması tip kaynağı, sapma testiyle SQL'e bağlı** (seçilen) | Down zorunluluğu dosya düzeyinde; RLS/politika/GRANT/tetikleyici SQL'i olduğu gibi gözden geçirilir; ek araç bağımlılığı yok; ileri→geri→ileri testi kolay | Drizzle şeması ile SQL'in elle senkronu → sapma testi gerekir |
| B. `drizzle-kit generate` + `migrate` | Şemadan otomatik SQL | Down yok (G-08 ihlali); RLS/GRANT yine elle; korunan `drizzle/**` klasöründe üretilmiş dosyalar gürültüsü |
| C. Ayrı migration aracı (ör. node-pg-migrate, dbmate) | Olgun up/down | Yeni bağımlılık ve ikinci sürücü (`pg`) üretim yoluna girer; ADR-003'teki tek sürücü ilkesini zayıflatır |

**Karar:** Seçenek A.
1. **Dosyalar:** `packages/db/migrations/NNNN_<snake_ad>.up.sql` + `.down.sql`, dört haneli artan numara. Her dosya tek transaction'da uygulanır (`CONCURRENTLY` gerektiren indeks ayrı, transaction dışı işaretli migration — ihtiyaç doğunca bu ADR'ye ek).
2. **Defter:** `wms_meta.schema_migrations(version, name, checksum_sha256, applied_at, applied_by)`; şema `wms_meta`'nın sahibi migration rolü; `wms_app`'in bu şemada **hiçbir yetkisi yok**. Uygulanmış bir migration'ın dosya özeti değişmişse koşturucu **durur** (`MIGRATION_CHECKSUM_MISMATCH`) — `check:protected`'a ek çalışma anı savunması.
3. **Koşturucu:** `packages/db/src/migrate.ts`; komutlar `pnpm db:migrate` (bekleyenleri uygula), `pnpm db:rollback -- --to <NNNN>` (yalnızca `WMS_ENV` ∈ `local|ci|staging`; prod'da gerçek veri kaybettiren down kullanıcı onayı ister — PROTOCOL §Onay kaynağı). Tek koşu kilidi: `pg_advisory_xact_lock` **doğrudan** bağlantıda (pooler'sız). Bağlantı **yalnızca** `DATABASE_URL_DIRECT` (migration rolü); `DATABASE_URL` (uygulama rolü) ile çalıştırılırsa ret.
4. **Roller migration'da yaratılmaz:** `wms_app` altyapı adımıdır (yerelde `01-roles.sh`, Neon'da T-105 hazırlık iş akışı). İlk migration (`0001_baseline`) `wms_app`'in varlığını ve `NOSUPERUSER NOBYPASSRLS` olduğunu **denetler**, değilse durur; `public` şemasında `CREATE`'i `PUBLIC`'ten alır; `wms_app`'e yalnızca `USAGE` verir. Her tablo yetkisi kendi migration'ında açıkça `GRANT` edilir (varsayılan yetki yok).
5. **RLS şablonu (her tenant tablosu):** `tenant_id uuid NOT NULL`, `(tenant_id, id)` benzersiz + bileşik FK, `ENABLE` + `FORCE ROW LEVEL SECURITY`, `USING` + `WITH CHECK` `tenant_id = NULLIF(current_setting('app.current_tenant_id', true), '')::uuid` (15 §DB sözleşmesi). Platform (global) tabloları RLS'siz olabilir ama yalnızca gereken `GRANT`'ları alır ve ADR-016'da listelenir.
6. **Drizzle şeması:** `packages/db/src/schema/*.ts` tip kaynağıdır; migration yerine geçmez. Sapma testi (`tests/integration/schema/drift.int.test.ts`): migration'lar uygulanmış veritabanında `information_schema` sütun adı/tipi/NULL'luğu Drizzle tablo tanımlarıyla birebir.
7. **Dağıtım sırası (staging/prod):** `deploy-staging.yml` → migration adımı (**uygulama dağıtımından önce**, doğrudan Neon bağlantısı, migration rolü) → Fly dağıtımı → smoke. Genişlet–taşı–daralt: yeni sürüm eski şemayla, eski sürüm yeni şemayla çalışabilmelidir; daraltma (sütun silme) ayrı ve sonraki dağıtımda.
8. **Test:** `pnpm test:int` her koşuda boş veritabanında tüm migration'ları uygular; ayrıca `migrations.int.test.ts` ileri → tümüyle geri → ileri döngüsünün hatasız olduğunu ve geri sonrası şemanın boş (yalnızca `wms_meta` defteri) kaldığını doğrular.

**Sonuçlar ve riskler:**
- Elle senkron riski sapma testiyle kapatılır; test kırmızıysa paket birleşmez.
- Neon'da sahip rolünün (`neondb_owner` benzeri) migration rolü olarak kullanılabilirliği ve `wms_app`'in SQL ile oluşturulabilirliği T-005d sonucuna bağlıdır (Q-06). Olmazsa T-105 BLOCKED raporlar; bu ADR yeniden açılır.
- `pg-boss` kendi şemasını kurar: kurulum migration rolüyle (`pnpm db:migrate` sonunda), uygulama `migrate: false` ile bağlanır (T-115).

**Doğrulama:** `migrations.int.test.ts` (ileri/geri/ileri, özet uyuşmazlığında ret, `DATABASE_URL` ile çalıştırmada ret), `drift.int.test.ts`, staging dağıtım koşusunda migration adımının yeşil olması (T-106).
