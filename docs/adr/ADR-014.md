# ADR-014: Kimlik doğrulama kütüphanesi ve oturum modeli — Better Auth (yalnızca kimlik katmanı)

**Tarih / Durum:** 2026-10-05 · **önerildi** (architect, Faz 1 planı; ADR-012 rev.: Supervisor karara bağlar, auth etkisi nedeniyle `security-reviewer` incelemesi zorunlu)

**Bağlam:**
- Şartname (`02 §Oturum`): kısa ömürlü erişim + yenileme + oturum iptali; **her yazmada güncel üyelik/yetki kontrolü**; yönetici/süper yönetici için MFA; hassas işlemde yeniden doğrulama; sağlayıcılar Google, Microsoft, e-posta. AC-18: çıkarılan kullanıcının eski token'ıyla yazma reddedilir.
- Yığın: Next.js 16.3.8 App Router (ADR-001), Drizzle 0.45.3 + postgres.js 3.4.9 (ADR-003, T-005b), transaction-mode pooler (ADR-004), tenant verisi yalnızca `withTenant` ile (I-02). Kod İngilizce, UI Türkçe (ADR-002).
- Kimlik ≠ üyelik (`04 §Kimlik`): kullanıcı birden çok tenant'a üyedir; tenant tabloları RLS altındadır. Auth kütüphanesi tenant tablosuna yazmamalıdır (yazarsa `withTenant` dışından yazar → I-02 ihlali).

**Karar:** Seçenek A — Better Auth 1.7.7, **yalnızca kimlik katmanı** olarak (`packages/auth`).
1. **Kapsam sınırı:** Better Auth yalnızca platform kimlik tablolarına yazar: `users`, `sessions`, `accounts`, `verifications`, `two_factors`, `auth_rate_limits` (ADR-016). Tenant, üyelik, rol, davet, audit **bizim kodumuzdadır** (`packages/domain/identity`, `withMembership` — ADR-016). `organization`, `admin`, `multiSession`, `apiKey` eklentileri kullanılmaz.
2. **Oturum:** opak oturum belirteci, `HttpOnly; Secure; SameSite=Lax` çerez; `session.cookieCache` **kapalı** (her istekte DB doğrulaması → çıkış/iptal anında). Süreler A-39. Girişte yeni belirteç (oturum sabitleme yok). "Kısa ömürlü erişim token'ı + yenileme rotasyonu" şartı bu modelde **sunucu taraflı opak oturum + kayan süre + anında iptal** ile karşılanır (A-40).
3. **Yetki tazeliği (AC-18'in asıl dayanağı):** oturum yalnızca kimliği kanıtlar. Her tenant yazması `withMembership` ile **aynı transaction'da** üyeliği (`ACTIVE`), tenant durumunu (`ACTIVE`) ve rol iznini doğrular (ADR-016). Üyelikten çıkarılan kullanıcının oturumu geçerli kalabilir (başka tenant'ları için), ama o tenant'a yazamaz.
4. **Parola:** Argon2id (`@node-rs/argon2` 2.2.1, MIT; Better Auth belgesindeki `password.hash/verify` kancası). Politika A-41. Parola, belirteç, TOTP gizi loglanmaz/audit'e yazılmaz (I-12, G-09).
5. **MFA:** `twoFactor` eklentisi (TOTP + yedek kodlar), `issuer: "Etkin WMS"`. Zorunluluk kapsamı A-38. Yeniden doğrulama: `requireRecentAuth(maxAgeSec)` yardımcısı (oturum oluşturma zamanı / son parola-TOTP doğrulaması); Faz 1'de mekanizma ve testi, kullanan işlemler (export, hesap kapatma) kendi fazında.
6. **Sağlayıcılar:** Faz 1'de e-posta+parola. Google/Microsoft yapılandırma kodu yazılır ama `AUTH_SOCIAL_ENABLED` kapalı bayrakla; istemci kimlikleri kullanıcı hesabı ister (Q-14, A-37).
7. **Hız sınırı:** Better Auth `rateLimit` **DB depolamalı** (çok makinede tutarlı); giriş/parola sıfırlama/2FA uçları için daha sıkı kurallar (değerler T-112'de, A-41 ile birlikte).
8. **CSRF/kaynak:** `trustedOrigins` yalnızca uygulamanın kendi kökeni (`BETTER_AUTH_URL`); Server Action'lar Next'in origin denetimine ek olarak kendi oturum denetimini yapar.
9. **Sürüm kilidi:** `better-auth`, `@node-rs/argon2` tam sürüm (`STACK.md`); yükseltme = kart + T-112/T-114 testleri yeşil.

**Sonuçlar ve riskler:**
- `packages/auth` ham Drizzle istemcisine (`@wms/db/internal`) erişmek zorundadır → lint izin listesine yalnızca bu paket eklenir (T-111, korunan değişiklik).
- Better Auth tablo/alan adları bizim snake_case şemamıza `modelName`/`fields` eşlemesiyle bağlanır; eşleme hatası çalışma anında ortaya çıkar → T-112 entegrasyon testi gerçek şemaya karşı kayıt/giriş/çıkış/2FA akışını koşar.
- Risk: oturum belirtecinin DB'de nasıl saklandığı (düz/özet) kurulu sürümde doğrulanır (T-112); düz saklanıyorsa DB okuma sızıntısı = oturum ele geçirme → `security-reviewer` bulgusu olarak kaydedilir, azaltma (kısa süre, `sessions` tablosuna yalnızca `packages/auth` erişimi) uygulanır.
- Risk: kütüphanenin hızlı yayın temposu; kilitli sürüm + yükseltme kartı ile yönetilir.
- Sosyal giriş ve doğrulanmış alan adı olmadan e-posta doğrulaması kapalıdır (A-50); bu, staging'in demo kapsamıyla sınırlıdır.

**Doğrulama:** T-112 entegrasyon testi (kayıt, giriş, çıkış sonrası eski çerezle istek → `UNAUTHENTICATED`, oturum iptali, 2FA zorunlu rolde 2FA'sız giriş tamamlanmaz, hız sınırı); T-114 bağımsız güvenlik testleri; AC-18 (T-120) ve AC-04 (T-128) `@AC` testleri.
